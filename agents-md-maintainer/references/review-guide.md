# 审查指南

按本轮需要读取：范围与判断 → 审计；报告 → 交付；验证 → 行为候选；应用 → 用户已批准修改。无需为每次审计执行完整评测。

## 范围与事实

沿用已授权上下文，取得目标文件、工作目录、相关项目根、可取得的 Codex 版本及本次判断所需的工具和权限信息。运行模型和计划迁移模型分别记录；优先用户指定、会话元信息或可信配置。配置默认值未必是当前运行值，模型自述不能证明身份。

识别影响目标的全局与项目指令、覆盖文件、相关嵌套文件及显式引用。定向核对当前官方发现规则；至少区分：

| 状态 | 所需依据 |
| --- | --- |
| 已发现 | 文件确实存在且已读取，或仅发现但无法读取并说明限制 |
| 按文档推定适用 | 当前工作目录、指令链及相关配置符合已核实的发现规则 |
| 证实已加载 | 当前运行记录明确支持；仅找到文件、依据文档推算或模型自称均不够 |

当前官方文档按全局层和项目根到工作目录的路径描述发现规则；同一目录的 `AGENTS.override.md`、`AGENTS.md` 与备用文件名存在选择关系，不应把它们全部拼接。任意兄弟或更深层目录的文件不能因为存在就认定已加载。遇到版本、字节上限或配置未知，限制相应结论，详见 [来源记录](sources.md)。

只定向读取相关配置字段，例如备用文件名或文档大小上限；不输出完整个人配置，不读取凭据、无关会话历史或扫描整个主目录。无法取得的上层文件、配置与模型信息列为范围限制，不阻止可完成的本地审计。

从说明、文件清单、代码、测试定义、配置和必要小样例取证。大型科研仓库不默认读取原始数据、完整表达矩阵或大日志。`doc/context.md` 可作证据入口，但仍需核实维护状态和对应文件，不能仅凭名称认定权威。

## 判断每条规则

把复合句拆为可独立判断的义务，记录实际文件位置、条件和例外。保留可与后续文件对齐的原文；不为了定位小文本默认计算全量哈希。

每个候选回答：原来防止什么错误？现在为什么值得调整？什么证据会使它继续保留？推测用途标为推测，没有历史记录就不编造失败。

主要原因可多选：重复或通用描述、仓库变化、模型变化、工具配置变化、作用域或加载问题、缺少依据。主要建议选择一种：

| 建议 | 判断要求 |
| --- | --- |
| `KEEP` | 仍提供项目约定、授权边界、必要质量要求、难以可靠推导的信息或实际防错价值 |
| `COMPRESS` | 语义和作用域等价，缩短后仍保留条件、义务、例外与权威来源 |
| `MOVE` | 细节仅对特定任务有用，能指明目标、入口、读取时机和根级保留信息 |
| `UPDATE` | 项目或适用官方证据足以说明路径、命令、能力假设或范围需要修正 |
| `REMOVE_CANDIDATE` | 疑似无增量价值；明确删除范围、反证和仍需完成的验证，不能当作自动删除许可 |
| `NEEDS_EVIDENCE` | 证据不足，指出改变判断所需的最小证据 |

重点约束：

- 真正重复要求语义和作用域相同；局部覆盖可能有意不同。项目保护规则可以等价去重，但不能整句移除其中独立的保护义务。
- 代码可推导仍可能发现昂贵、易歧义或错误代价高。保留用户选定的可靠失败记录与特殊环境限制。
- 失效路径须有重命名、实际调用或维护文档等依据；尚未生成、需挂载或仅在特定条件出现的路径不能直接判错。
- 由测试或配置替代指令前，核实机制存在、覆盖相关场景并确实会运行。测试文件存在或“以后可以写测试”不构成替代证据。
- `MOVE` 应说明原文件保留的入口句、目标材料、触发条件与可达性。只搬到另一份无条件必读长文，或没有可靠入口，不算完成精简。
- 不能用更自主的一般指南替代项目特定审批；样本排除、统计定义、数据不可逆操作及外部发布等边界不会由模型能力推导出授权。

## 模型升级与指令冲突

只检查适用官方指南或本地问题指向的项目，不把下表变成所有任务的必填清单。先确认目标模型、产品范围与相关规则的适用状态；规则未加载、工具不可用或配置变化，应先作为各自原因分析，不能直接归因于模型升级。

| 关注点 | 对应项目证据与候选方向 |
| --- | --- |
| 上下文读取 | 是否无差别必读全部文档；按实际任务提供入口，同时保留原规则防止的遗漏 |
| 测试范围 | 是否对小修改重复全量验证；先查必要检查、隔离条件和实际覆盖，再提出调整 |
| 确认边界 | 区分真实审批要求与对已批准同范围操作的重复确认；安全本地执行范围须有用户授权或可核实约定 |
| 完成条件 | “第一版即停止”是否与已授权的运行、检查、修复目标冲突；缺少明确条件时可提出局部补充，用户只要方案或审查时不得推进实施 |
| 委派与输出 | 是否与可用工具、任务规模、用户期望不符；不一律增加并行、固定格式或更长报告 |

沿具体异常定向追溯当前请求、适用的 `AGENTS.md` 和相关 Skill；记录冲突双方的原句、文件位置、触发条件及已知加载状态。区分显式要求与审计者解释，遵守实际指令层级，不让 Skill 指南扩大用户授权。只报告相关外部 Skill 的问题，不借机扫描或修改整个技能目录。

每项模型相关候选串联：**适用官方陈述 → 受影响规则或缺失位置 → 项目证据 → 建议文本 → 验证状态**。证据不足用 `NEEDS_EVIDENCE`；必要补充使用 `UPDATE`，注明“原文无此条款”及拟插入位置。确认、测试和停止条件的放宽或收紧都属于行为改变，进入实验候选；避免只做删减审计。

按影响优先呈现少数重要发现；同类项可合并，但保留各处位置。正常规则无需逐句重述，关键保留项简述理由。不输出总分或固定删减比例。

## 相称的验证

语义等价去重、已经核实的路径更新，以原文对照、有效引用和作用域检查为主。改变确认、测试、读取上下文、完成条件或委派要求，应设计针对性任务对照；未执行标为待验证，不强迫每次审计跑完整评测。

比较同一个目标模型下的 A（旧指令）与 B（候选指令）。固定任务、代码和输入基线、Codex 版本、权限与其他有效指令，记录并尽可能固定推理设置及任务实际使用的工具配置，使用独立会话或隔离副本。存在未控制差异时披露限制，不能称为受控 A/B。不能在已加载旧规则的同一线程里改文件后，把后续工作冒充 B。

若已有可取得的启动记录，比较实际装配的指令与技能目录；源码快照一致不单独证明会话输入一致。发现额外差异时保留观察结果并说明限制，不为取得整齐的对照自动重跑。

任务应覆盖规则原本防止的失败场景，预先定义正确性、边界遵守与必要检查，再比较返工、无关读取、交互次数及可取得的成本。一轮成功仅是初步证据，不能用成本收益抵消正确性退步。多模型共用时覆盖实际模型，或限定结论；只做目标模型 A/B 不能证明变化由模型升级造成。

默认提出对照方案，不自动启动昂贵分析或额外付费调用。实际执行沿用已授权资源与隔离输入。静态检查、脚本执行、Agent 行为、原生技能发现、规则 A/B 分开记录；缺少工具或网络时记录限制，不补造成功结果。

涉及委派时，审阅范围与工具、用量统计注明是否包含子任务；主任务事件流未展示子任务操作时，补取现成轨迹或明确证据范围，不能据此认定操作未发生。

## 应用已批准项

用户可以一次批准若干编号；明确且仍有效的授权不重复询问。执行前取得对应报告和审计基线，重新读取目标文件并比较原文、上下文与依赖。文件已变化时重新对齐已批准项，保留新增或修改内容；无法确定对应关系的条目暂不应用，说明具体冲突，仍可完成其他独立且明确的批准项。

只修改批准编号及已授权的配套文件。`MOVE` 若依赖尚未获准的新入口或目标文档，不能只删除原文并宣称成功。行为性候选优先取得验证结果；未验证时先解释具体限制，仅在用户知情后明确批准才应用，不默默改变授权或科研决策。

以原文和最终 diff、现有版本记录或必要的局部备份保留恢复依据；不能假定未提交内容已在 Git 历史中。应用后检查 diff、引用可达性和规则作用域，报告批准项、实际变更、检查结果及未执行项。

未经授权的候选、全局配置、其他工具指令文件、业务代码和科研参数保持原样。不自动 commit、push、清理未提交变更、删除历史或加入“每次维护指令”的自我扩张规则。
