# 提出一个好科学问题

## 核心合同

把选题视为 `研究者偏好 → 知识张力 → 候选问题 → 现实约束 → 文献审计 → 可判别设计 → Human 选择`，而不是由方法、数据集或热门术语反向制造故事。

最终形成一个主问题和至多一个备选问题。好问题必须同时满足：研究者真正愿意长期追问；承重前提有既往证据；终点仍存在可区分的未知；当前资源可以做出决定性检验；不同结果会改变理论、实验或临床决策。

把“不撞车”表述为有范围的检索结论：截至某日，在列明的来源和查询范围内，未发现与问题、场景、方法和预期结论均高度重叠的研究。不得承诺绝对新颖。

## Human ownership

- Human 决定喜欢什么、愿意承担什么风险、可投入哪些资源，以及最终选择哪个问题。
- Agent 负责访谈、结构化候选、查找真实证据、暴露冲突与盲点、提出最小充分检验并比较 trade-off。
- 不替 Human 发明兴趣，不把热度、论文数量或可用算法当作“有前景”的充分证据，也不在证据不足时替 Human 批准立项。

## 工作流

### 1. 建立研究者偏好与约束画像

一次只追问 1–3 个最能改变候选空间的问题，逐轮收敛：

- 真正好奇的现象、人群、疾病、系统或尺度；
- 更喜欢描述、预测、因果、机制还是转化问题；
- 已有数据、样本、模型、技术、协作与可访问临床场景；
- 时间、预算、统计功效、伦理与技能边界；
- 不愿做的方向、不可接受的风险，以及希望研究结果改变的决策。

把推测标为 `待确认`。不要因为用户提到某个方法，就把方法当作科学问题。

### 2. 建立“已知—张力—重要性”证据地图

用真实来源区分：

1. 哪些事实较稳定；
2. 哪些结果互相矛盾、存在多个解释或适用边界未知；
3. 哪个未解决点一旦回答，会改变理论、实验、靶点、分层或临床决策。

对陌生大方向，可使用 `bear-onboard` 建立概念版图与演化脉络；已有清晰方向时只做必要的定向检索。不要把“文献少”直接解释为有价值的空白。

### 3. 生成少量正交候选

从参考框架的六类知识张力中生成 3–5 个候选。候选之间应改变问题本身，而不只是替换算法。每个候选先写：

- 一句话科学问题；
- 它匹配研究者偏好的原因；
- `受支持的桥梁`：已有证据支持哪些承重前提；
- `未解决的终点`：现有研究尚未区分什么；
- 至少两个竞争性解释；
- 若得到答案，会改变什么。

此阶段只做宽筛，不为所有候选运行昂贵的完整检索。

### 4. 运行硬门预筛

逐个候选判为 `淘汰`、`需重构` 或 `进入文献审计`。任何一项为否都不得直接晋级：

- 核心构念能否操作化测量？
- 是否至少存在一个会使主假设不成立的结果？
- 问题是否能区分至少两个合理解释？
- 推断强度是否与可获得设计匹配？
- 独立分析单位、比较、时间窗口和目标估计量能否定义？
- 最小充分设计是否在资源与伦理边界内可做？
- 回答后是否会改变一个明确的下一步决定？

不因“看起来新”“很热门”或“能发文章”跳过硬门。

### 5. 对入围问题做真实文献审计

最多选择两个入围问题。优先使用 `bear-propose` 完成撞车、安静区支撑与潜在挑战的联动审计；只有需要补强单项时再使用 `bear-scoop`、`bear-support` 或 `bear-counter`，避免重复检索。

审计必须同时回答：

- 最近的直接撞车、问题孪生和方法孪生是谁；
- 哪些承重前提得到直接、部分或间接支持；
- 哪些反例、边界条件、替代解释或方法缺陷最危险；
- 检索日期、来源、查询角度、覆盖盲点与未检索范围是什么。

若 bear Skills 或 `scimaster-cli` 不可用，不得伪造其结果；说明缺失并用当前可用的真实学术检索降级，保留同样的审计字段。调用外部 Skill 前遵循 `references/evidence-orchestration.md` 的写入边界。

### 6. 设计最小可判别实验

不要先堆方法。为每个竞争模型写出不同的可观察预测，再选择能最大区分它们的最小设计：

- 明确 Population/System、Exposure/Intervention、Comparator、Outcome、Time、Level；
- 用一句话定义 estimand、独立单位、调整条件和不确定性；
- 规定支持、削弱和无法区分各模型的结果；
- 按需要加入时间顺序、剂量反应、扰动、救援、正交测量、阴阳性对照或外部重复；
- 写出最可能的失败模式及失败后仍能学到什么。

实验意义来自区分解释或排除重要模型，不来自技术数量。阴性结果若能排除关键解释，仍可有高信息价值。

### 7. 检查转化链路与前景边界

只有能够写出以下链路时，才主张存在转化潜力：

`研究发现 → 可操作的标志物/靶点/分层/流程 → 具体使用者与决策 → 预期获益 → 实施条件与风险`

区分机制意义、工具价值与临床净获益；动物或体外机制不能直接外推为临床效用。把“有前景”拆成可审计因素：未解决问题的重要性、结果的决策杠杆、后续研究空间、技术与样本可达性、竞争窗口、可复现性和实施障碍。

### 8. 比较并交还 Human 选择

对入围问题按以下维度给出 `高 / 中 / 低 / 未知`，每格必须附证据或理由：

- 研究者偏好匹配；
- 知识缺口清晰度与撞车风险；
- 承重前提的文献支持；
- 可证伪性与模型区分度；
- 数据、样本、方法、时间与伦理可行性；
- 实验信息增益；
- 转化链路可信度；
- 前景与竞争窗口的耐久性。

先揭示致命弱点和未知项，再陈述优势。除非 Human 事先给出权重，否则不要把多维判断压成伪精确总分。由 Human 明确选择主问题、备选问题或返回重构。

### 9. 形成 Good Question Brief

使用模板交付：偏好与约束、稳定已知、核心缺口、主问题、竞争模型、可证伪假设、estimand、最小充分设计、偏倚与边界、文献审计、实验意义、转化链路、证据标准、不同结果对应的下一步，以及仍需 Human 决定的事项。

标记成熟度：

- `exploring`：仍在大方向或偏好澄清；
- `candidate`：已结构化但未完成真实文献审计；
- `evidence-audited`：已记录检索范围、撞车、支撑与挑战；
- `ready-for-study-design`：硬门全部通过，Human 已选择，且关键未知已显式记录。

只有最后一种状态才可转交 `research-project-workflow` 建立项目级 Question/BRIEF。成熟度不是科学正确性认证。

## 停止与诚实边界

- 用户的偏好或资源约束会实质改变方向但尚不清楚时，暂停候选定稿并追问。
- 发现直接撞车时，先比较不可区分部分，再选择缩小、改变边界、改变决定性检验或淘汰；不得只换标题。
- 没搜到撞车不等于原创；搜到支持不等于终点已被证明；文献稀少既可能是机会，也可能是不可行或无价值。
- 横断面关联不得写成因果或机制；体外/动物扰动不得直接写成患者获益。
- 不把一项研究包装成同时解决描述、预测、因果、机制与转化全部层级。
- 不负责项目 scaffold、证据登记、RESULT、handoff 或正式报告渲染；问题选定后按需转交相应 Skill。
