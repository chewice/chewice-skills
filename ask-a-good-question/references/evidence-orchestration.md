# 真实文献与 bear Skills 编排

## 1. 定位与来源

本 Skill 可组合外部项目 [bear-research-skills](https://github.com/fei0810/bear-research-skills)，但不复制或改写其源码。上游使用 CC BY-NC-SA 4.0；把它视为可选、独立安装和独立更新的检索能力。

bear 输出基于 `scimaster-cli` 的真实检索，但仍受数据库覆盖、索引时延、查询词、语言、付费墙和未发表工作的限制。其报告是证据输入，不是最终立项裁决。

## 2. 使用前检查

1. 检查所需 `bear-*` Skill 是否在当前会话可用。
2. 运行 `sci --version`；若未安装或未认证，说明缺失，不自动安装或写入凭证。
3. 使用某个 bear Skill 前完整读取它自己的 `SKILL.md`，遵守其检索与输出合同。
4. 记录调用日期、版本、查询范围和输出位置。

若不可用，可使用其他真实学术检索。只依赖论文题目或摘要时要标明证据深度；不要从模型记忆补论文、作者、DOI 或结论。

## 3. 路由表

| 当前任务 | 优先能力 | 使用边界 |
| --- | --- | --- |
| 对陌生大方向建立空间与时间认知 | `bear-onboard` | 用于理解概念与演化，不直接生成最终问题 |
| 只看概念邻域 | `bear-map` | 不回答新颖性或可行性 |
| 追溯关键问题或种子论文 | `bear-trace` | 不替代近期撞车扫描 |
| 对单个候选查撞车 | `bear-scoop` | “未检索到”不等于原创或安全 |
| 对入围候选做完整立项证据审计 | `bear-propose` | 首选；已包含撞车、安静区支撑与挑战，不再机械重复三项 |
| 检查某个承重前提 | `bear-support` | 支持前提不等于终点问题已得到回答 |
| 主动寻找反例、边界和方法威胁 | `bear-counter` | 没找到反对证据不等于主张正确 |

探索初期围绕具体困惑做必要检索：澄清概念、核实观察、比较解释或寻找新线索。无需先通过设计检查或形成完整候选。每次检索先明确它想帮助理解什么，结果回来后说明理解发生了什么变化，以及新的追问。

准备投入或比较成熟候选时，通常先对研究者选定的 1–2 个问题运行 `bear-propose` 以控制成本；其他候选可保留，按研究者的取舍分批处理。只有报告暴露出特定证据缺口时，再补单项检索，不自动扩大为全面审计。

## 4. 撞车审计的比较单位

不要只比较标题或关键词。逐篇比较四轴：

1. 问题：是否区分同一个知识缺口或竞争模型；
2. 场景：人群、组织、疾病阶段、物种或应用是否相同；
3. 决定性检验：关键测量、干预、时间结构和设计是否相同；
4. 预期贡献：最终会声称的知识增量是否不可区分。

若四轴高度重叠，改关键词或换算法不能消除撞车。先说明已有工作已回答什么、还留下什么；由研究者选择改变边界、继续探索、重复验证或搁置。重复验证应说明其价值，不宣称原创新问题；改变问题后更新相关检索。

审计结论保留日期、覆盖范围、最近邻和实际盲点，可参考以下句式，不必机械照抄或在每段重复限制：

> 截至【日期】，在【工具/来源】及【查询角度】覆盖范围内，发现【N】个直接撞车候选、【N】个问题孪生和【N】个方法孪生；最近邻为【文献】。由于【盲点】，不能据此宣称绝对新颖。

## 5. “有文献支持”的正确结构

按当前问题需要区分以下内容；描述性探索可以先核实观察和测量，无需凑齐模型：

- `B1..Bn 承重前提`：若不成立，整个问题失去依据；
- `U1 未解决终点`：研究拟真正回答的未知；
- `A1..An 替代解释`：同一现象的其他合理模型。

用 `bear-support` 检查 B，用 `bear-counter` 检查 B 和候选假设的边界。如果文献已经直接回答 U，说明哪些追问仍开放；如果 B 没有支持，区分尚未检索到、未经检验与已有反证，讨论是否先核实 B。研究者可选择继续探索，证据状态如实保留。

比较解释时，核实其共同面对的观察及额外假设。奥卡姆剃刀帮助安排优先检验的路径，不能代替证据判断。反例也可揭示时间、人群或测量上的新线索；总结突出它如何改变问题，只保留影响当前判断的限制。

## 6. 审计记录的最小字段

完整审计时，每个候选保留以下信息；探索中的定向检索只记录实际问题、来源、结果及必要的范围限制，不伪装成完整审计：

- candidate ID 与精确问题句；
- 检索日期、工具和版本；
- 实际查询词或查询角度；
- 数据库、时间、语言与文献类型范围；
- 最近撞车及四轴重叠理由；
- 承重前提及其支持级别；
- 会改变解释或选择的反例、边界或方法问题，以及由此产生的追问；
- 空结果及其可能解释；
- 已知盲点与未检索范围；
- 原始报告相对路径或链接。

所有科学事实都回链真实来源。综述适合建立版图，但关键主张优先回到原始研究、系统综述或指南。

## 7. 写入边界

bear Skills 通常会在当前目录创建 `{topic-slug}/` 及 Markdown、HTML、BibTeX 等文件。调用前：

- 若用户已指定项目，使用项目内明确的 `evidence/question-selection/<candidate-id>/` 或用户指定目录；
- 若用户只想讨论且没有写入位置，先说明将产生哪些文件并取得目标目录；
- 不在仓库根目录静默生成多个 topic 文件夹；
- 不覆盖既有报告；保持不同候选和不同检索日期可区分；
- 只在 Good Question Brief 中摘要并链接原始报告，不把检索报告伪装成最终科学判断。

## 8. 降级与停止

- CLI 缺失、认证失败或额度不足：说明具体原因并按可用能力降级；完成同样范围记录的真实替代检索可计入审计，未完成则保留实际成熟度，不标为 `evidence-audited`。已有审计的效力取决于当前问题与覆盖范围，不因一次补查失败自动失效。
- 检索结果过少：扩大同义词、相邻领域和“抢发者标题”角度；仍为空则把“研究不足”和“可能新颖”并列。
- 结果互相矛盾：不要投票决定真相；提取边界差异并把它们转成候选的决定性检验。
- 直接撞车密集：呈现已回答和仍开放的部分，由研究者选择下一步；问题改变后更新检索，旧审计仅适用于原有表述及范围。
