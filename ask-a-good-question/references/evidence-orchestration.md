# 真实文献与 bear Skills 编排

## 1. 能力与路由

必装前置项目 [bear-research-skills](https://github.com/fei0810/bear-research-skills) 使用 CC BY-NC-SA 4.0；按 README 安装全系列八个技能并配置 SciMaster，独立安装和更新，不复制或改写其源码。报告是证据输入，仍受数据库覆盖、索引时延、查询词和可访问深度限制。

首次使用时确认前置安装与配置已完成，已有状态可沿用；未完成时先处理环境准备，不把替代检索当作已满足前置要求。实际调用时读取对应技能自己的 `SKILL.md`，并用 `sci --version` 确认 CLI 能启动；这不证明认证、网络或额度可用。已配置后服务失败时停止该 bear 路径，说明原因并使用可用的真实替代检索，结果标明实际能力；不自动安装或写入凭证，不从模型记忆补论文。环境配置见 [README](../README.md)。

| 当前任务 | 优先能力 | 使用边界 |
| --- | --- | --- |
| 建立领域概念与演化认识 | `bear-onboard` | 单纯入门可直接使用，不必进入选题 |
| 只看概念邻域 | `bear-map` | 不回答新颖性或可行性 |

| 完整立项证据审计 | `bear-propose` | 已包含撞车、支撑与挑战，不机械重复三项 |
| 检查承重前提 | `bear-support` | 支持前提不等于终点问题已解决 |

探索期围绕当前未知做必要检索，记录需要核实的判断与本轮范围，说明结果如何改变理解。CNS、奠基论文及作者路线可作线索，不是每轮必经节点。准备投入或比较成熟候选时，通常先审计研究者选定的 1–2 个问题，其他候选保留；只针对实际缺口补查。

## 2. 领域认识的依据与边界

- **背景与发展**：用综述定位概念与关键转折，说明新观察、解释或测量能力解决了什么、留下什么。影响候选的判断回到原始研究或适当的证据综合。
- **共识**：结合适用的共识文件、系统综述或相对独立研究的汇合证据，说明共同支持的认识、适用范围与分歧。没有正式文件时可描述证据一致性；引用量或反复转引不能单独认定共识。
- **单项发现与争议解释**：记录对象、设计、测量与推断层级，区分结果不同与解释不同，留意共享队列和数据。
- **前沿与热点**：用近期原始研究、预印本或正在开展研究的可核实信息，说明正在解决什么及已取得何种证据。记录检索日期、时间窗口和发表状态，区分技术热度与知识增量。
- **知识空白**：对照最近邻已回答和仍未知的部分，检查是否只是定义、测量或检索不足造成的表面空白。描述、复现和适用边界均可构成研究目标。

每项认识链接真正支持它的来源，注明背景、支持或挑战关系，以及题目、摘要或全文等实际阅读深度。压缩为共识、冲突、假设和空白时保留适用边界、证据强弱与重要异议，避免把单项发现升级为共识。只展开影响当前候选的部分，记录格式见 Brief 的领域证据表。

领域梳理不等于完成候选审计。分工检索时明确待查主张、范围和共享定义，汇总时检查证据重用与覆盖遗漏。

## 3. 比较撞车与证据支持

撞车逐篇比较四轴，不只比较标题或关键词：

1. **问题**：是否回答同一个缺口或区分同一组模型；
2. **场景**：人群、组织、阶段、物种或应用是否相同；
3. **决定性检验**：测量、干预、时间结构和设计是否相同；
4. **贡献**：最终的知识增量是否可区分。

高度重叠时说明已有工作已回答什么、还留下什么，由研究者选择改变边界、重复验证或搁置。改关键词或算法不能消除实质重叠；重复验证说明其目的，不宣称原创新问题。

支持检索区分三个对象：

- **承重前提**：问题成立依赖什么；
- **未解决终点**：研究真正拟回答什么；
- **替代解释**：哪些合理模型也能解释现象。

核查前提的支持及边界。终点已被回答时寻找仍开放的追问；前提支持不足时区分尚未检索到、未经检验与已有反证，决定是否先核实它。描述性探索可先查观察与测量，不强凑模型。反例应指出它如何改变问题或下一步。

## 4. 记录实际覆盖范围

定向检索只记录当前问题、日期、实际查询范围、来源、结果和必要限制。达到足以支撑本轮判断的范围即可总结；仍有关键缺口则明确下一步，不能称“全部证据已搜完”。完整审计另保留：

- 候选标识与精确表述，工具、版本、查询词，以及数据库、时间、语言和文献类型范围；
- 最近邻来源、四轴重叠理由与仍开放的部分；
- 承重前提的支持程度、重要反例及其引出的追问；
- 空结果、可能原因、盲点与未检索范围；
- 原始报告路径或链接。

空结果可按需补查同义词和相邻领域，仍为空则如实记录，不能据此认定新颖。结论冲突时比较来源、设计和边界，不按数量投票。

替代检索完成同样范围记录时可计入审计；未完成则保留实际成熟度。已有证据按适用性保留，问题改变后只更新受影响的检索，旧审计仍归属于原表述及范围。

## 5. 写入位置

bear Skills 通常在当前目录创建 `{topic-slug}/` 及报告。已指定项目时使用 `evidence/question-selection/<candidate-id>/` 或用户指定目录；只讨论且没有位置时，在调用会落盘的能力前说明产物并取得目标目录。

不同候选、日期的报告保持可区分，不覆盖既有报告或在仓库根目录静默生成目录。Brief 只摘要并链接原始报告，不重复保存整份检索内容。
