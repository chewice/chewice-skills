# R 分析

只在目标文件为 `.R` 时读取本指南。

## 让对象变换保持可见

围绕当前科研对象，自上而下写真实分析。常见形态是：

```text
研究问题与上游对象
-> 读取或重载
-> 查看结构与分组
-> 变换或拟合
-> 查看候选结果或诊断
-> 显式记录科学选择
-> 用选定结果继续
-> 保存下一步需要的证据
```

这是一组可选动作，不是强制提纲。对象含义不变时，让核心对象稳定向下推进；只有科学含义改变，或 baseline 需要保留以供比较时，才创建新对象。

默认把分析写在顶层，使语句可以按顺序逐行运行并在中间停下。不要把整段分析包进 named function、`main()` 或 `run_analysis()`。函数不禁用：比较循环里的短匿名函数可以保留；稳定的逐元素技术核仍可在内联案例被理解后抽取。

持久对象（读入的表、矩阵、上一步 RDS 列表、排名、比较表）使用能说明其内容的名字，长度适中，例如 `counts`、`metadata`、`seu`、`markers`，或项目已经采用的明确名称。后面还要读的对象不用 `tab`、`dat`、`tmp`、`obj`、`input`、`main`、`c`、`mat`、`stats` 这类占位名。方法缩写（`dge`、`voom`、`fit`、`de`）和路径句柄 `fn` 可保留。不要为了对齐会话变量去改 RDS / list 的字段名。

紧凑名只留给 `fn`、匿名函数形参，以及几行内用完的绘图句柄。多行分析循环里的循环变量也应能读懂。

## 分段说明与逐段执行

每段围绕一个当前分析目的，用标题和一两句说明交代为什么做、需要观察什么。标题清楚时不再另写重复解释；方法或参数的选择依据放在对应调用附近。分段应支持选择一行或多行送入同一个 R 会话，在观察点停下检查真实输出，再续写下一段。

例如，已确认输入为至少五行五列的矩阵时：

```r
# 读取并检查表达矩阵 ----
# 查看行列标识和部分数值，为后续样本对齐提供依据。
counts <- readRDS(counts_path)
dim(counts)
counts[1:5, 1:5]
```

保留已载入对象，避免为下一段启动新的 `Rscript` 并重复读入。修改上游筛选或参数后，重跑受影响的下游段；选中运行依赖前文已执行，不要求每段自带读入和初始化代码。

决定标题格式前，先查看目标文件和邻近 R 脚本。保留项目已有的 `#`、`##`、`#### ----`、`====` 或其他轻量约定。

新文件没有邻近先例时，可用 `# 检查样本构成 ----` 这样的轻量标题；只有用户或仓库明确要求 RStudio / VS Code OUTLINE 层级时，才统一成 `# 1. Title ----` 及其 title-first 层级。不要只为统一标题而重写既有脚本。

section 按科学语义组织，例如检查样本构成、比较候选维度、选择 lineage、查看 null control、为下一 part 保存对象。优先保留 `# [问题]`、`[检查点]`、`[决策点]`、`[待判断]` 和紧邻的科学备选。`# 读取数据`、`# 保存结果` 这类短导航注释，只要确有帮助就可以保留。不要为环境、dry-run、路径切换说明或报告 URL 写操作横幅，除非那一行本身就是科学选择。

## 保留观察点和决策点

观察性检查是分析的一部分。选择最小、但足以支持下一判断的视图：

```r
dim(counts)
counts[1:5, 1:5]
head(metadata)
names(metadata)
unique(metadata$group)
summary(metadata$nFeature_RNA)
table(metadata$sample, metadata$group)
seu
p
```

读入后展示少量真实内容，不能只显示维度或“读取成功”。矩阵或宽表用 `dim()` 配合局部切片；metadata / annotation 用 `head()`，需要选字段或水平时再加 `names()` / `unique()`；list 或科学对象查看与当前问题相关的组件。小矩阵按实际尺寸调整切片，不照抄五行五列；稀疏矩阵直接取小切片，需要普通矩阵显示时只转换该切片，不把整个对象 `as.matrix()`。不要为预览创建通用 helper。

筛选、合并、变换或拟合后，在下一判断需要时再次展示相关内容、摘要或诊断图。不必每个对象堆三种打印，也不必每行代码都跟输出。

在明确的交互式项目中可以使用 `View()`，但不要默认加到非交互脚本中。紧邻调用保存的诊断图，往往比断言更能支持科研决定。

`data_path` 可以写在读入之前。不要在首次读入并观察之前，就根据论文、GEO 或其他先验填写依赖盘上内容的 `*_keep`、分组水平、`model_formula`、协变量向量或 cutoff；那些选择放在观察之后的 `# [决策点]`。

当研究交接因此更清楚时，使用 `[检查点]`、`[决策点]`、`[专家判断]` 或项目已有的同类注释。证据必须先于选择：

```r
names(metadata)
unique(metadata$group)
table(metadata$group, useNA = "ifany")

# [决策点] 先看上面的 names / unique / table，再填写子集或公式。
# group_keep <- ...  # 检查后根据当前问题填写；不自动选第一个水平。
# 需要该选择的子集或模型语句，在决定明确后再写入并执行。
```

生成尚未运行的代码时，把选择写成待判断并注释掉依赖该选择的语句，不把 `NA` 或其他占位值传进模型。实际运行时由分析者根据证据决定；agent 能据当前任务和观察作出决定时自主继续，关键科学取舍无法确定时才询问用户。不得编造最优值、cluster identity、cutoff 依据或生物学结论。

不得凭惯例、来源范例或 package default，静默补上会改变分析含义的 `resolution`、cutoff、top-N、model family、受 seed 影响的选择或同类参数。项目没有既定值时，要么基于当前数据比较候选，要么在调用紧邻处保留明确的未决值。只要 default 会改变解释，它仍然是科学选择。若用户指向一份项目内参数来源，可以把起始值写在调用附近，并标明这是起始方案而不是已验证最优；仍须先观察盘上字段与水平，再用该起始方案，而不是用先验覆盖观察。

不要为了“显式”而把未请求的 package defaults 全部写进调用，也不要自行增加 algorithm switch、seed、plot sampling size、palette、DPI 或一组额外诊断。先完成能回答当前问题的最小比较；只有邻近项目已有约定，或某个设置确实影响当前判断时才写出并解释它。

“生成 marker summary”“做 differential analysis”一类产物描述，并未自动确定 comparison unit、identity、contrast、test、assay/slot 或 threshold。缺少这些决定时，保留一个带注释的 pending block 或在该处停止；不得为了让脚本表面完整而选一个常见 `FindAllMarkers()` / statistical test。若前一步选择实际上不进入该统计分析，也要直接说明，而不是制造虚假的对象依赖。

## 先做一个代表性案例，再批量化

当某项计算在当前数据上仍需理解时：

1. 选一个代表性 gene、sample、pathway、group 或 lineage；
2. 把完整计算内联写出；
3. 查看中间值以及合适的诊断或对照；
4. 在主线中修正假设；
5. 只有逐元素技术核稳定后，才提成局部函数并应用到显式集合。

若内联原型能解释模型或校验批量结果，即使批量化后也可作为证据保留。文件开头预先定义一个隐藏尚未验证分析的函数，顺序是不对的。减少用函数包装整段分析，不禁用函数。

## 只抽取稳定的技术核

局部函数适合稳定的逐元素模型、重复技术转换、bootstrap，或已经遮蔽主线的重复绘图；两个块看起来相似，本身不是函数门槛。

cutoff、目标分组、annotation、root / terminal、候选参数和其他科学决定必须留在 helper 外部。新 helper 放在首次使用附近。为保持主线清楚，它可以读取紧邻的少量技术常量，但不能用隐藏 default 承载科学决定。

较大的 sample、method、condition 或 lineage 分支，只要能让每个实验独立阅读和修改，就可以继续保持独立。只有真实漂移已经出现——例如某分支引用 stale variable，或意外生成不同输出契约——才抽取最小共同操作。

## 区分观察与硬契约

用局部内容、摘要和诊断图支持判断。减少 `stopifnot()` / `stop()`，不禁用。不要用它们做 dry-run、缺参填写或单元发现闸门；在会话中检查结果，依据证据决定是否继续，不把普通检查变成逐步人工审批。

只有继续执行会静默污染科学含义时，才保留简洁断言，例如：

- metadata 行与矩阵列不再对齐；
- 必需 identifier 重复；
- 必需分组或 lineage 字段缺失；
- 模型输入方向或长度不可能成立。

不要把普通探索改造成 validation subsystem，也不要保存 pass marker。

## 工作目录与路径

若项目约定从脚本所在目录运行，在 `library()` 前进入该目录（已在该目录则跳过），并打印 `getwd()` 与 `.libPaths()`。随后把 `data_path`、`out_path` 写成相对该目录的路径，紧接着 `dir.create(out_path, showWarnings = FALSE, recursive = TRUE)`。

逐文件读取时，先赋 `fn`，再读，再查看，再复用 `fn` 读下一个文件：

```r
fn <- file.path(data_path, "TODO_INPUT")
counts <- read.delim(fn, check.names = FALSE)
dim(counts)
counts[1:5, 1:5]

fn <- file.path(data_path, "TODO_METADATA")
metadata <- read.table(fn, header = TRUE, sep = "\t")
dim(metadata)
head(metadata)
```

RDS 重载用同一形状。嵌套的 `readRDS(file.path(...))` 仍允许，作为更短的写法，但不是逐行会话的首选。用项目实际文件和读取函数；不要把 `raw_feature_bc_matrix`、`Matrix::readMM` 或 mtx.gz 当成通用默认。

沿用项目已有的路径锚点。不要把某个仓库里的 `setwd("scripts/...")` 字符串当成通用默认值，也不引入机器特定绝对路径。

## 允许真实的科研边界

下列做法是合理的：

- 保存 marker 或候选表，交给人工编辑，在后一 part 继续；
- 重载人工编辑后的表格，或上一步 RDS/QS 对象；
- 不同方法读取同一 baseline，各自保留为独立脚本；
- 缓存真正昂贵的科研结果，使绘图或解释可以不重算而继续修改；
- 若项目已有这种习惯，用清楚注释的 `if (FALSE)` 作为昂贵可选重算块的窄人工开关。

这些边界应说明科研交接是什么，不得扩张成运行发现、retry、通用 mode 或状态追踪。

## 只保存有用途的证据

表格、图、对象或 cache 只有在支持检查、解释、下游分析或复现时才保存。尽量靠近赋予它含义的分析块保存，也可以放在明确的阶段边界。不要强迫每个脚本同时输出所有类型或打印结尾运行摘要。

脚本确实运行过，且用户希望保留分析记录时，可以在末尾记录实际观察、局限或下一问。否则明确标为待判断。
