# 局部辅助函数

## 函数门槛

定义函数前依次判断：

1. 同一技术动作是否真实重复至少两次，或明确将对多个元素执行？
2. 抽取后是否让主分析顺序更容易读？
3. 函数能否保持单一职责、短小且输入输出显式？
4. 抽取后是否仍能在调用附近看到关键科学参数和决定？

前两项任一为否时，优先内联。第 3 或第 4 项为否时，缩小函数边界。

## 适合的局部函数

- 用统一尺寸和命名保存一组图；
- 对多个样本执行相同的窄技术调用；
- 对每个基因拟合同一种模型；
- bootstrap、resampling 或 purity 等独立计算；
- 读取和标准化多个同构基因集文件；
- 重复生成同类网络或热图。

## 不适合的函数

- 只调用一次、十几行即可读懂的核心分析；
- 名为 `run_pipeline()`、`process_everything()` 的总入口；
- 内置 QC cutoff、annotation 标签、lineage 或 gene set 的 wrapper；
- 仅为缩短文件而把连续主线搬到另一个文件；
- 为未来可能复用而提前建立 class、registry、factory 或 config system。

## 编写约束

- 把函数放在首次使用前附近，不建公共 helper 文件。
- 使用明确参数，不依赖大范围全局变量。
- 返回单一、可说明的对象；避免隐式写多个外部文件。
- 技术默认值可以有安全默认；科学参数应由调用处显式传入。
- 函数体包含必要检查，但不要吞掉错误。
- 复杂度增长时先问是否应保留重复，而不是继续分层。

## 允许重复的情形

不同 sample、stage、method 或 lineage 的脚本可保留平行结构，使各分支的输入、参数和
输出独立可读。若只有两三个短块，重复往往比通用 wrapper 更清楚。

只有同时出现以下情况才抽取：

- 重复是技术性的而非科学决策；
- 多处修改已经产生漂移风险；
- 抽取后调用仍能表达分支差异。
