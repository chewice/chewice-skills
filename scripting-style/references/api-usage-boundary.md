# API 使用边界

## 原则

把用户或项目提供的 API 当作不透明、已存在的能力。脚本的职责是正确准备输入、显式调用、
检查返回并保存产物，而不是复制或猜测 API 内部。

## 调用顺序

1. **确认契约**
   - API 名称和加载方式；
   - 必需输入、参数和返回值；
   - 用户明确说明的前置条件。
2. **准备输入**
   - 保持对象构建、过滤和分组在主线可见；
   - 在调用前检查类型、维度、标识符和缺失值。
3. **加载 API**
   - 按当前项目约定 `source()`、`import` 或调用命令；
   - 靠近首次使用位置，避免无关 API 批量加载。
4. **调用**
   - 显式写出会改变分析含义的参数；
   - 只使用已知参数，不凭函数名推断隐藏选项。
5. **检查返回**
   - 验证返回对象结构、关键字段、数量或诊断图；
   - 错误应暴露在调用边界，不用宽泛异常处理吞掉。
6. **保存**
   - 区分原始 API 返回、整理后表格、诊断图和下游对象。

## 允许与禁止

允许：

- 记录 API 在哪个脚本阶段加载；
- 根据已知契约准备参数；
- 为重复调用写一个窄局部 wrapper，但必须保留关键参数和调用顺序；
- 对返回结果做结构检查和必要整理。

禁止：

- 打开未授权的 API 源文件；
- 根据调用名称推断内部算法；
- 在分析脚本中重写 API；
- 为统一接口建立跨项目 adapter 层；
- 把关键生物学选择藏进 wrapper 默认值；
- 复制范例项目的机器特定加载路径。

## 未知契约的处理

若 API 契约不完整，先从用户提供的文档、当前调用示例或可见函数签名确认。若缺失信息会
改变结果含义，明确提出最小问题。不要用猜测补齐科学参数。
