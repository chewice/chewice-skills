# 长期项目：拆分、归档与中断恢复

仅在入口超预算、记录/索引持续增长或要整理历史时读取。本机制控制每次加载量，同时让仍有研究价值的信息留在持久文件中；它不能保证任何模型都能完整记住已读材料。

## 最少的层次，明确的去向

| 载体 | 保存什么 | 何时读取 |
| --- | --- | --- |
| 唯一 `context.md` | 当前目标、有效约束、关键事实/限制、恢复点和导航 | 每次恢复完整读预算内入口 |
| 问题或主题记录 | 该问题的观察、解释、决定理由、反例、开放问题、证据引用 | 当前任务命中这个主题时 |
| 必要的专题索引 | 按科学问题/数据对象分组的入口、状态和检索线索 | 分支太多，入口无法直接列出时 |
| 原始证据与历史来源 | 数据、代码、产物、既有记录或整理前快照 | 核验、追溯或重新解释时 |

这些是职责，不是强制目录树。短项目保持单文件即可；优先链接现有笔记、分析说明和产物。只有必要内容没有可复用载体时，才在用户指定或项目已有文档位置添加最少的文件，例如与入口同级的 `context-sample-design.md`。文件名按内容选择，不预建每个项目都用不上的目录。

一项事实的详细依据只在一个地方维护；入口和索引提供短提示与引用。主题记录不复制整个项目目标、全局状态或所有分支，不产生多份互相竞争的项目摘要。当前仍有效的跨问题约束和限制留在入口。

## 控制增长

- 入口默认预算为 4,000 个字符；主题记录和专题索引以 8,000 个字符为拆分参考。按实际工具限制调整，但不能只因超限而不断抬高预算。原始数据、日志和不可改写的来源不受此编辑预算约束，读取它们仍须分段或定向检索。
- 更新入口前，先用引用替代已持久化的细节，合并重复表述，将不影响当前动作的已完成/暂停分支移出活动区。当前的反例、风险、阻塞或未决决定不能因“旧”被隐藏。
- 导航本身超预算时按研究主题或数据对象分组，入口保留组的含义、检索线索和路径；只有组索引也超预算才继续细分。不能把全部旧条目挪到一个无限增长的 `archive.md` 后视为解决。
- 主题过长时按可独立理解的子问题或证据批次拆分，保留必要共同条件及其来源。历史阶段可标为暂停、已完成、被取代或待重核，并保留“为何停止/什么条件下重启”。不按会话次数机械切块。
- 每份记录有从入口出发的明确路径。索引只负责导航，不递归装载其所有内容；没有变化时不重写稳定历史。

## 整理已经过长的入口

不要先生成一份更短的总结再删除原文。尤其不能只读文件头或搜索命中，就宣称保留了所有研究状态。

1. **保留来源。** 在改写前保留原始文件的完整快照和指纹，或确认已有可恢复且包含未提交内容的等价副本，同时记下待改写入口的指纹。以该不再改写的副本为扫描源，标明历史来源，不作为另一份当前入口；不可仅依赖可能没有包含本次内容的 Git 版本。用户禁止新增文件时先利用现有可恢复载体；无可靠去向的有价值内容保留原处，报告尚未完成的整理。
2. **分段扫描并落盘。** 按限长片段连续覆盖全部源文件，包括尾部和长单行。每处理一段，把有价值的内容保存在对应记录中，留下紧凑的“源片段 → 去向或剔除理由”核对项；跨片段的句子、表格、代码块和论证要续读到语义完整再归类。区分真实源内容与 Agent 推断。
3. **保留可恢复进度。** 扫描无法在本轮完成时，将扫描源路径/指纹、已覆盖范围、下一位置、正在跨段处理的内容和已写出的目标路径保存在持久的整理记录中；它是临时工作记录，不是第二份权威摘要。在原入口开头放一条整理进度链接，使下一会话无需旧对话就能找到它；记录添加链接后待改写入口的指纹。先保存片段去向，再推进游标。下一轮核对扫描源和现行入口是否变化后继续。
4. **核对保留情况。** 检查原始目标、数据含义与适用版本、重要事实、证据与不确定性、用户决定及理由、失败/反例、被放弃方案与重启条件、未完成工作及下一步都有去向。可剔除重复内容和无研究价值的工程流水，不能只留下结论。逐一核对新引用的文件及定位片段实际存在。
5. **最后切换入口。** 全源覆盖和上述核对完成后，再核对待改写入口的指纹；整理期间若有新增进展或用户决定，先保留并核对差异，不能用旧快照覆盖新状态。随后才把 `context.md` 替换成预算内的当前状态与导航。核对前，原入口仍权威，新记录标为整理中；不要让未完成迁移的局部记录冒充全貌。切换后重新读取入口，沿当前问题以及暂停/反例分支的路径试着恢复，确认不需要上一轮对话即可找到依据和下一步。

整理记录只用于此次迁移核对，不发展成永久登记系统。原始快照是否清理由用户授权范围决定；保留它不等于要求每轮加载它。自动压缩对话、Agent 自述或“文件写入成功”都不能代替源内容覆盖与引用核对。

## 日常暂停与重新激活

分支暂停时，保存当时的问题、重要观察与依据、停止理由和重启条件；入口仅保留影响当前工作的约束以及可检索路线。重新激活时定向读取该分支，核对其数据版本、用户决定和假设是否仍适用，再把需要的状态提升到活动区。

新决定或输入变更先更新入口中的有效条件，并标出受影响的主题待重核；不要为了省字只在新记录里写一句“与旧版不同”。无法当轮核完的下游结果明确标注适用性未确认，保留其历史依据，继续不受影响的工作。

恢复所需信息超出当前可读预算时，保存已覆盖范围和剩余入口，再分段继续。不能用越来越短的摘要替代尚未检查的证据，也不能承诺长项目的全部历史会常驻 Agent 上下文。
