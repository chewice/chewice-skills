# 上下文恢复与更新

## 读取预算与恢复顺序

1. 遵循项目指令找到入口：用户指定位置优先，否则使用已有的 `docs/context.md`；保持既有入口位置。入口缺失时，仅在用户要求建立上下文后创建最小入口，否则继续有依据的工作并说明未持久化状态。结合当前请求识别活动问题，保留原始目标。
2. 预算内的小型入口直接完整读取，不为普通读取计算 SHA256。超预算时按 [`long-projects.md`](long-projects.md) 分段恢复、整理；输出受限时缩小片段，不把截断当成读完。
3. 从入口选择当前问题需要的记录片段，再核对实际依赖的输入、代码或产物。先搜索标题、对象名或关键词，再读取有边界的范围；不沿全部链接递归展开。
4. 足以确定目标、约束、必要证据及下一动作时停止扩展。区分已读取、已核实和仅有入口的材料；未加载不是不存在，文件存在不等于结果已核验。

未读完入口、输出被截断或必要材料不可达时，说明未覆盖范围，不假定剩余部分没有约束；继续不依赖它的工作。

仅在分页续读或跨会话整理需要确认来源是否变化时，使用带指纹校验的只读工具 [`context_read.py`](../scripts/context_read.py)；它每次调用都会读取源文件并计算 SHA256，不作为小型入口的默认读取方式。将下列 Skill 路径替换为实际路径，从项目目录运行：

```bash
python3 /path/to/research-context/scripts/context_read.py docs/context.md
python3 /path/to/research-context/scripts/context_read.py docs/context.md --start 2000 --expect-sha256 'FIRST_PAGE_SHA256'
```

默认每次返回最多 2,000 个内容字符，可用 `--chars` 调小。`start` / `end` 是从零开始、右端不包含的 Unicode 字符位置，长单行也会分页。续读使用实际 `next_start` 和首段 `sha256`（替换示例的 `FIRST_PAGE_SHA256`）；来源变化时重新核对，不沿用旧位置。

完整片段须有完整 JSON、末尾 `window_complete: true`，且解码后的 `text` 长度等于 `end - start`；工具提示截断时即使末尾可见也不算完整，应缩小窗口重读。只有从头连续覆盖至 `eof: true` 才算通读。脚本不能证明会话剩余容量足够，读取量仍须适配实际预算。

无 Python 时可用 `wc -m` / `wc -l` 查看体量，`rg -n` 搜索，`sed -n` 分段读取；长单行须按字符切片并核对覆盖范围。需要识别续读来源是否变化时才使用 `sha256sum` 等版本校验方法。

## 入口保存什么

沿用既有格式，无须固定模板或空章节；按恢复工作的需要安排内容：

| 内容 | 恢复时需要知道什么 |
| --- | --- |
| 目标与当前问题 | 原始研究目标、当前子问题、目前停在哪里 |
| 有效决定与边界 | 用户已决定什么，当前必须遵守哪些条件；建议与已决定事项分开 |
| 当前事实与推断 | 已核实的数据对象含义、关键数量或质量事实；暂定解释及其边界 |
| 输入与证据入口 | 当前使用的文件/对象、影响适用性的版本或处理状态、具体标题或定位词 |
| 未决问题与阻塞 | 会改变当前判断的反例、冲突、未完成核验、待用户决定事项 |
| 下一步与恢复点 | 下一动作及原因、前置条件；中断工作已完成什么、还需核对什么 |
| 其他问题入口 | 暂停或已完成分支的检索线索、状态及记录路径；过多时指向专题索引 |

链接说明“包含什么、何时要读”。相对路径以所在文档为基准，用稳定标题或关键词定位；行号需配合文件版本。有效决定、跨问题约束、当前限制与阻塞放在入口靠前位置。

入口默认保留研究状态及必要的来源、版本和恢复条件。日志、调试过程、完整表格等由原产物、README 或 manifest 承载；用户明确要求记录的内容按其要求保存，同时控制加载量。

## 冲突与过期信息

- **输入、输出与检查结果：** 核对实际产物、代码和执行依据，区分当前版本与旧版本。
- **解释与推断：** 保留假设、依据和不确定性，不因文件较新就认定解释成立。
- **人的决定：** 以用户明确作出的决定为依据，不把建议写成已批准决定。超出既有授权的研究方向、证据资格、样本取舍、主要方案或主结论选择，说明依据和取舍后交由用户判断。

有实质性备选方案时，比较输入、假设、局限和代价；无法共用输入时说明比较限制。可以暂不选择或保留多个解释；人的选择不能替代科学依据。

冲突能核实的更新，不能确认的标明待核实。输入或用户决定改变时，更新当前问题、后续任务和相关主题的适用范围，标出受影响结果待重核；保留仍有价值的历史依据，不只追加一条说明。

## 写回与责任

重要观察、输入/产物变化、用户决定或下游问题出现后及时保存；长任务在可恢复节点落盘。切换任务、中断、总结、交接或会话压缩前，保存进展、未完成检查、关键条件和下一入口。

先保存依据，再更新入口并核对路径可达、表述一致和长度预算。旧状态在原位置替换，不追加命令流水；入口用 `Updated` 标明更新时间，历史决定时点、证据版本和被取代关系按需保留。无实质变化时不重写。
