# 上下文恢复与更新

`context.md` 是唯一的当前状态与导航入口。事实和决定的详细依据在各自研究记录或产物中保留一份，入口只保留影响当前行动的摘要及可定位引用。恢复工作依靠入口和证据，不依靠上一轮对话仍在模型中。

## 读取预算与恢复顺序

1. 遵循项目指令找到入口：用户指定位置优先，否则使用已有的 `docs/context.md`。结合当前请求明确要恢复的问题，不将新请求自动当成取消原目标。
2. 检查文件体量并限长读取。默认入口预算为 4,000 个 Unicode 字符，完整读完预算内入口；不要仅凭工具返回成功就认定已读完。超预算时按 [`long-projects.md`](long-projects.md) 分段恢复、整理，不强行把全文堆入当前会话。
3. 从入口选择当前问题需要的记录片段，再核对实际依赖的输入、代码或产物。先搜索标题、对象名或关键词，再读取有边界的范围；不沿全部链接递归展开。
4. 足以确定当前目标、约束、所依赖证据及下一动作时停止扩展。区分已读取、已核实和仅有入口的材料；未加载不是不存在，文件存在也不等于结果已经核验。

入口中影响当前动作的用户决定、限制、冲突与阻塞应靠前。尚未读完入口、工具输出被截断或必要材料不可达时，不假定剩余部分没有约束；说明未覆盖范围，继续不依赖它的工作。

可用随 Skill 提供的只读分页工具，无第三方依赖。将下列 `/path/to/research-context` 替换为 Skill 的实际路径，并从项目目录运行：

```bash
python3 /path/to/research-context/scripts/context_read.py docs/context.md
python3 /path/to/research-context/scripts/context_read.py docs/context.md --start 2000 --expect-sha256 'FIRST_PAGE_SHA256'
```

默认每次最多返回 2,000 个内容字符，可用 `--chars` 调小。`start` / `end` 是从零开始、右端不包含的 Unicode 字符位置，长单行也会分页。以实际返回的 `next_start` 续读；将 `FIRST_PAGE_SHA256` 换成首段 `sha256`，文件变化时重新核对，不沿用旧位置。完整片段须有完整 JSON、末尾 `window_complete: true`，且解码后的 `text` 长度等于 `end - start`；工具若提示截断，即使末尾仍可见也不算完整。`eof: true` 仅说明片段已到文件尾，只有从头连续覆盖才算通读。

工具输出限制和会话剩余预算可能更小；输出不完整时缩小片段重读，不跨过未收到的内容。字符数不等于 token 数，脚本不能证明模型的剩余上下文足够。无 Python 时可用 `wc -m` / `wc -l` 查看体量，再用 `rg -n` 定向检索、`sed -n` 分段读取；极长单行还须按字符切片，配合 `sha256sum` 等方法核对来源版本、覆盖范围和末尾。

## 入口保存什么

沿用既有格式，无须固定模板或空章节；按恢复工作的需要安排内容：

| 内容 | 恢复时需要知道什么 |
| --- | --- |
| 目标与当前问题 | 原始研究目标、当前子问题、目前停在哪里 |
| 有效决定与边界 | 用户已决定什么，当前必须遵守哪些条件；建议与已决定事项分开 |
| 当前事实与推断 | 已核实的数据对象含义、关键数量或质量事实；暂定解释及其边界 |
| 输入与证据入口 | 当前使用的文件/对象、影响适用性的版本或处理状态、具体标题或定位词 |
| 未决问题与阻塞 | 会改变当前判断的反例、冲突、未完成核验、待用户决定事项 |
| 下一步与恢复点 | 下一动作及原因、前置条件；中断工作已完成什么、还需核对什么 |
| 其他问题入口 | 暂停或已完成分支的检索线索、状态及记录路径；过多时指向专题索引 |

链接应说明“包含什么、何时要读”，不要只列文件名。相对链接按所在文档的位置解析；优先用路径与稳定标题或关键词定位，行号需配合文件版本，不能当永久锚点。跨多个问题的有效约束必须在入口可见，不能只埋在其中一个分支。

支持性、null、negative、contradictory 与 inconclusive evidence 同样保留。当前仍受其限制时，在入口保留短提示与依据；已暂停分支的详细观察、决定理由、放弃原因及重启条件放在主题记录中，可从入口检索到。

原始日志、长篇调试过程、完整表格、搜索结果和重复材料通常不塞进入口。工程细节由 git history、README、manifest、`docs/ref` 等载体承载；改变研究输入、产物入口、推断适用性、人的决定或中断恢复条件时，更新相应条目。必要的科学来源与版本信息不能作为“工程噪声”删掉。

## 冲突与过期信息

- **输入、输出与检查结果：** 核对实际产物、代码和执行依据，区分当前版本与旧版本。
- **解释与推断：** 保留假设、依据和不确定性，不因文件较新就认定解释成立。
- **人的决定：** 以用户明确作出的决定为依据。新结果不能自行撤销研究取舍，也不能把建议升级成已批准决定。

报告影响当前工作的冲突；能核实的更新为当前状态，不能确认的标明待核实。输入或决定改变时，在入口标明受影响的结果/任务待重核，并更新相关主题的适用范围，避免归档中的旧结论被当作现行依据。

## 写回与责任

输入或产物改变、获得重要观察、用户作出决定、方向调整或发现影响下游的问题时，由 Main Agent 更新变化部分。旧状态在原位置替换，不按日期追加命令流水；研究记录中的决定时点、证据版本和被取代关系可按需要保留，入口用 `Updated` 表示本次状态更新时间。

先保存研究依据与主题记录，再更新入口中的当前状态和链接；核对路径可达、表述一致且入口未超预算。不存在可复用载体时，在已授权维护范围内新增最少的记录，拆分细节见 [`long-projects.md`](long-projects.md)。无实质变化时不重写。

不等到会话结束才保存：重要结果已核验或用户改变决定后及时落盘；长任务在可独立恢复的节点保存进度。任务切换、中断、总结、交接或会话压缩前，保存尚未记录的进展、未完成检查、关键条件和下一读取入口。恢复点只写到足以继续，不把执行日志搬进摘要。

Main Agent 统一维护入口及共享研究记录。Sub-agent 返回建议更新项，或在明确分配且不冲突的独立产物中写入；不直接编辑共享入口。入口缺失且用户未要求创建时，继续能依据现有资料开展的工作并说明未持久化状态；用户已要求建立上下文则创建最小入口。
