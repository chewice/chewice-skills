# 按月归档的当日与阶段回顾

## 触发与保存边界

“总结今天的任务”“总结当前阶段”“先保存进展”触发回顾：即时整理可见工作，将待审阅记录写入所属月份的月报并展示 context 变更候选，不等月底才总结。用户只要聊天预览或明确禁止落盘时，仅在回复中提供。普通分析、切换任务、中断或运行时自动压缩不自动写月报或 context；不能保证找回此前已丢失且未保存的信息。

沿用用户指定或项目既定的月报位置；否则使用 context 总入口同级的 `monthly/YYYY-MM.md`，尚无入口时可用 `docs/monthly/YYYY-MM.md`，不因此建立 context。拆分主题 context 不改变月报位置，不为每个主题另建月报目录。只有历史日报时，新记录按月保存，旧日报留在原位；仅明确要求迁移时才整合旧文件，不同时生成日报副本。

一个月使用一份文件，以工作日期和时间升序分节；跨月工作按已知发生时间进入各月。写入前定向读取相关日期和问题的既有片段：同日仅补充实质进展，不复制整日或整月内容；补记插入对应日期，保留实际整理时间。工作时间不详者在整理日下标明未知，不补造日期或时刻。

记录工作日期、整理时间及其时区；确认后再记录确认时间，三者不混用。沿用用户/项目时区，本用户默认 `Asia/Shanghai`，时间可写 `2026-09-22T18:30:00+08:00`。每项工作附简短研究问题或任务名，便于人阅读及必要时检索，不额外生成月度索引或重复综述。

## 回顾包含什么

先说明覆盖范围：本次可见的对话、用户提供的记录、实际读取的任务与产物，以及未覆盖的任务或时段。不凭文件修改时间断言执行时间或成功，不将“未发现记录”写成“没有做过”；未知归属、时间和执行状态如实注明。

按下列四项组织，内容简单时用短段落即可：

1. **做了什么：** 已完成、进行中、阻塞及产物路径；计划、实际执行和核验结果分开。
2. **拒绝或暂缓了什么：** 谁作出的决定、理由、适用范围及重启条件。区分用户拒绝、Agent 未获采纳的建议、暂缓、技术失败与有效的 null/negative 结果；没有依据时不替用户作决定。
3. **生信分析：** 本次涉及的输入/样本版本、比较与方法、主要观察、技术核验、推断限制和证据定位，保留会改变判断的信息；当天未开展或无法确认时明确说明，不凑章节内容。
4. **哪些值得进入 context：** 只提出影响后续判断、避免重复错误或支撑恢复的变化，包括必要的技术状态、负面证据和未决问题；同时审视哪些旧状态应被替换或迁出，不把所有月报条目自动晋升为长期上下文。

## 展示与确认变更

候选以“日期＋条目编号”稳定定位，例如 `2026-09-22-C01`；同日新增编号继续递增，不重用。将 **新增 / 替换 / 迁出 / 必要拆分** 放在同一清单，注明目标文件、具体文本或旧→新差异、必要理由及依据。替换时定位旧条目；历史迁出说明月报日期片段或已有产物去向，仍有效状态拆分则说明主题位置、职责及总入口路由。列明有关联的变化，避免只批准路由却没有对应内容。按 [`context.md`](context.md) 检查预计长度；没有值得更新的内容时直接说明，不为凑条目改写。

- “总结”“方案不错”本身不授权 context 写入。用户明确接受并要求应用所展示的变更，或在明确询问是否写入这些条目时肯定答复，即可执行；“把 X 记入 context”已授权 X，不要求再走一轮月报审核。
- 部分确认只应用可独立成立的指定内容，其余保持待审阅或按用户要求不采纳；按条目标记待审阅、已应用或不采纳，不把确认一项解释成整篇获准。若已批准的路由仍依赖未批准的目标文件，说明尚未应用并保留原文，不扩大授权。部分应用后的 context 也须检查长度及一致性；不能为使它达标顺手执行未批准的迁出。
- 审批绑定用户看到的文本和范围。写入前核对当前目标条目；若候选或其依据/目标状态发生实质变化，只重新呈现受影响差异，其他仍有效授权照常执行。普通短记录不为审批计算哈希。
- “已确认存档”与证据状态独立。获准写入的内容仍可属于观察、暂定解释、待核验事项或用户决定；不能因用户确认而抹去不确定性。例如“当前模型下未达 FDR 阈值”不能变成“没有生物学差异”。

实际写入遵循 [`context.md`](context.md)：先核对历史去向和来源，再局部更新，保留有效限制及恢复入口。确认时间、确认范围和实际应用结果记在同一月报的相应条目旁；写入失败时说明未完成，不提前标为已应用。直接写入请求可引用已有来源或可用对话定位，不为补审批形式额外建文档。

## 轻量验收

月报主要供人回顾，不进入 AGENTS.md 或启动时的默认读取清单。只有当前 context 无法回答一个具体问题、需核对历史或用户要求回顾时，才按问题名、日期或对象搜索并读取相关片段；不整月加载，也不递归展开全部历史。待审阅事项只是线索，不能冒充已批准决定或已成立结论。

迭代 Skill 时检查同月多日、补记与同日补充不重复；新会话不预读月报，有缺口才追溯；多轮更新替换旧状态并保留拒绝理由、负面证据和版本条件；仅总结不改 context，部分确认不扩大写入范围。结构校验通过不等同于行为验证。
