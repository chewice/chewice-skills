# 任务委派、交接与轻量核验

仅在授权允许且工作可独立开展时委派；否则由 Main Agent 直接完成，不把有依赖的任务强行并行。

## Main → Sub-agent

交代以下内容：

- **问题与交付：** 回答哪个具体问题，需要返回什么。
- **输入：** 必要来源、版本或处理状态，以及标题、关键词或对应版本的读取范围。
- **边界：** 允许读取和修改的范围、输出位置、不得改变的上游条件与用户决定。
- **核验：** 怎样检查工作是否正确完成，哪些条件不足时应报告未完成或不确定。

按预算提供必要上下文，注明尚未读取或核实的材料。独立核查提供原始依据与问题，不暗示预期结论。同一文件不分配给多个 Agent 同时修改，范围外问题返回 Main Agent 协调。

## Sub-agent → Main Agent

返回短发现、依据路径、实际检查及结果、假设、未决项和更新建议。分别说明执行状态、技术核验和科学判断；未运行的检查如实标注。

长篇依据写入分配的产物，保留影响判断的失败和反例。中断时持久化已完成范围、未核验部分、来源版本和下一动作，不能仅引用聊天记录。

## Main Agent 接收与继续

核对是否回答问题、依据能否定位、输入是否仍适用，以及结论是否超过检查范围；按疑点定向检查，不把 Sub-agent 自述当作验证。输入已变的结果先核对适用性；结论冲突时比较输入、方法、假设和证据，不按多数意见选择。

按 [`context.md`](context.md) 保存依据、更新入口，不将返回内容整段追加。缺少输入、核验失败或决定待定时，仅暂停依赖该条件的工作；恢复前核对条件是否满足。
