# 人类决策与验收场景

## 方案比较和人的决定

存在会影响研究判断的合理备选方案时，先围绕当前问题明确共同输入和评价标准，比较差异、假设、局限及代价。无法使用相同输入时说明差异如何限制比较，不强行排列优劣。

不要求每个任务都制造多个候选，不统一套用一组指标，也不要求每次比较都选出唯一方案。保留多个解释、暂不选择或继续收集证据都是有效状态。

Agent 可在授权范围内完成检查、修复和分析，依照已有决定推进。新的研究方向、证据资格、边界样本取舍、主要分析方案或主结论选择，应说明依据与取舍并交由用户决定；不得把建议写成用户已批准的决定，也不对已明确授权的事项反复确认。

人的选择记录为人的选择，不能替代科学依据。用户改变决定后，更新摘要与后续任务；检查正在进行或已返回的工作是否受影响，保留仍有意义的既有观察。

## 验收场景

这些场景检验工作行为与恢复能力，不简化为检查标题或关键词是否存在。

| 场景 | 预期行为 |
| --- | --- |
| 普通手工项目，已有一个上下文入口 | 直接恢复工作，不创建目录、编号或记录模板 |
| 项目没有 `context.md` | 不自动创建；继续有充分依据的工作，说明哪些状态尚未持久化 |
| 新会话接管 | 通过摘要及必要链接识别当前问题、判断依据、限制和下一步 |
| 没有可用的 Sub-agent | Main Agent 能直接开展同样的工作，不因缺少委派能力阻塞 |
| 分析完成且技术检查通过，但科学结果不确定 | 分别报告完成状态、检查结果和推断限制，不宣称研究成功 |
| 用户改变研究方向 | 摘要、任务委派和后续工作随之调整，不只追加一条说明 |
| 多个 Agent 返回冲突结果 | 保留差异并核查来源，不按多数意见选择结论 |
| Sub-agent 工作期间上游输入改变 | 接收时检查适用性，不直接将旧输入结果纳入当前状态 |
| 两个独立任务中只有一个被阻塞 | 仅暂停受影响的任务，继续其余已授权工作 |
| 中断前有重要进展或不支持主解释的证据 | 保存恢复入口和有价值的观察，不压缩成单纯的成功摘要 |
| 比较后暂不选择方案 | 保留开放问题与下一步证据需求，不强迫收敛 |
