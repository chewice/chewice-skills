# 任务委派、交接与轻量核验

Main Agent 负责目标理解、依赖协调、结果整合和与用户的交互，也可以直接执行任务。工具与授权允许，且委派确实有价值时，才使用 Sub-agent。没有 Sub-agent 时由 Main Agent 按相同原则继续，不因缺少委派能力阻塞。

适合委派的工作包括：中间信息多但结论简短的定向调查、可独立进行的证据核查、输入可比较的候选方案评估，以及共享稳定输入且互不依赖的下游任务。

读取短文件、明确的小修改和简单检查通常直接完成。不要为每一步创建 Agent，不把有依赖的任务强行并行。

## Main → Sub-agent

以简短说明交代以下内容，不要求额外合同文件或固定序列化格式：

- **问题与交付：** 回答哪个具体问题，需要返回什么。
- **输入：** 必要资料和产物路径，以及足以识别本次输入的版本或处理状态。
- **边界：** 允许读取和修改的范围、输出位置、不得改变的上游条件与用户决定。
- **核验：** 怎样检查工作是否正确完成，哪些条件不足时应报告未完成或不确定。

只提供完成该任务必需的上下文。需要独立核查时，提供原始依据和核查问题，避免把预期结论当作答案提示。

同一文件不分配给多个 Agent 同时修改。任务范围外的修改或新发现的问题，返回 Main Agent 协调；不自行扩展任务或覆盖其他分支成果。

Sub-agent 可以提出科学解释、候选方案及其批评，它们属于供整合的分析和建议，不代表人的最终决定。Sub-agent 不直接编辑共享 `context.md`。

## Sub-agent → Main Agent

返回足以核对和继续工作的信息：当前问题、执行是否完成、关键发现、依据及产物路径、实际执行的检查与结果、假设和未决问题，以及必要的下一步或上下文更新建议。

不默认回传完整日志、所有读取内容和无关尝试。影响判断的失败和反例必须保留。关键执行状态不能只存在于临时对话中；已有项目产物可承载细节时提供其入口。不要为满足交接格式额外建立目录或登记系统。

执行状态、核验结果和科学判断分别说明，不使用单一 `PASS/FAIL` 代表整个结果。例如：

> 执行已完成；样本映射与输出一致性检查通过；两种解释仍无法区分，证据不足以回答当前问题。

未运行的检查如实标注，不能根据文件存在或报告措辞推断验证已经发生。

## Main Agent 接收与继续

核对返回内容是否回答委派问题，关键依据是否可定位、输入是否仍适用，以及结论是否超过检查能支持的范围。根据影响与疑点定向检查，不要求默认重跑全部工作，也不直接把 Sub-agent 的自述当成已验证事实。

输入已经改变时，先判断对结果及下游的影响；不再适用的结果保留其来源与限制，不直接合入当前有效状态。多个 Agent 的结论冲突时，比较输入、方法、假设与证据，必要时补充核查，不以多数意见代替证据。

重要任务在执行前考虑检查方式，执行中和交接时使用与问题相关的核验。按实际需要选择，不要求统一测试框架，也不以技术检查通过认定科学结论成立。

保留真实依赖。缺少关键输入、验证失败或决定待定时，仅暂停依赖该条件的工作；其余已授权任务可以继续。恢复时核对所缺条件是否已满足。
