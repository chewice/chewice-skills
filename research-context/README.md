# research-context：科研项目上下文管理

`research-context` 帮助长期科研项目保留可追溯的工作记录，并让新会话从项目文件恢复当前目标、有效决定和下一步。适用于生物信息学等需要多轮分析、人工判断和跨会话协作的研究项目。

日常使用围绕三件事：**用短 context 保存当前状态，按月记录工作过程，经人工确认更新上下文。**

## 可以做什么

- **初始化项目约定：** 按请求生成或更新 `AGENTS.md`，保留已有规则，指向项目实际使用的唯一上下文入口。
- **恢复研究工作：** 新会话或压缩后对照当前 context 与必要来源，核对输入版本、有效决定、执行状态和未完成请求，再确定下一步。
- **查看分析进展：** 按分析步骤概览当前进展、主要结果和详细记录位置，再按需要展开相关记录及证据。
- **总结当日或阶段工作：** 将回顾即时写入当月月报，展示值得进入 context 的变更，供用户审阅。
- **维护短上下文：** 替换过期状态，将过程与历史移出启动入口；多个独立问题确需分别维护时，经确认拆成按需读取的主题 context，保留全局约束、负面证据和恢复线索。
- **处理长期项目：** 按需追溯暂停分支、读取超长旧记录，支持明确请求下的完整整理和任务交接。

它负责研究状态与记录管理。环境构建、分析脚本风格和正式报告分别由相应工具或其他 skill 处理。

## 运行必需依赖

| 场景 | 必需条件 |
| --- | --- |
| 日常恢复与整理 | 能读取 Markdown 和项目材料的 Agent、本 Skill 完整目录，以及已有记录的读取权限 |
| 保存月报、生成项目约定或写回 context | 相应目标目录的写入权限；写入范围沿用本次请求与下文确认规则 |
| 使用超长记录读取助手 | Python 3；[context_read.py](scripts/context_read.py) 仅使用标准库，不需要额外 Python 包 |
| 明确要求审查或精简 AGENTS.md | 可读取的 `agents-md-maintainer` Skill；仅此项操作需要，日常恢复不依赖它 |

本 Skill 的日常文档管理不要求 R、Node.js、数据库、MCP、联网或特定分析环境。Python 只在调用随附读取助手时需要。若需要实际委派任务，还需宿主提供任务委派能力；普通上下文恢复不以多 Agent 为前提。

## 项目中维护哪些文档

| 文档 | 内容 | 使用方式 |
| --- | --- | --- |
| `AGENTS.md` | 稳定协作约定、唯一 context 入口、写入确认边界 | 为 Agent 提供项目规则；不放月报路径、正文或维护流程 |
| context：总入口及可选主题文件 | 总入口保存目标、全局约束、当前焦点及分析进展索引；详细状态沿用已有记录或必要主题 | 先看进展与结果概览，再按任务展开相关章节及必要证据 |
| 月报 | 按时间排列的工作过程、研究取舍、分析记录、变更候选及确认结果 | 主要供人阅读；Agent 有具体历史问题时才检索相关片段 |

采用默认位置时，项目布局可以是：

```text
project/
├── AGENTS.md
└── docs/
    ├── context.md
    └── monthly/
        ├── 2026-09.md
        └── 2026-10.md
```

这是默认的单入口布局，文件按请求和实际需要创建。只生成 `AGENTS.md` 不会顺带建立 context 或月报；已有自定义入口则沿用，例如 `notes/study-state.md`。月报默认放在总入口同级的 `monthly/YYYY-MM.md`，用户指定或项目既定的月报位置优先；拆分主题后也保持这个位置。

## 怎么使用

在可以调用该 skill 的 Agent 中，可以直接使用下面的请求：

| 目的 | 示例请求 | 预期行为 |
| --- | --- | --- |
| 初始化 | `使用 $research-context，为这个项目建立 AGENTS.md 和 docs/context.md。` | 根据已有资料生成项目规则及最小上下文，不虚构研究结果 |
| 恢复 | `接着做这个项目，先告诉我目前状态、限制和下一步。` | 读取 context，按具体问题核对必要资料，不自动写回 |
| 进展索引 | `请把 context 按分析步骤、当前进展、主要结果、详细记录位置整理成索引，沿用已有文档，先给我看。` | 提供基于现有记录的索引候选，不另建每步文档或改写 AGENTS.md |
| 总结 | `总结今天的任务，供我审阅。` | 更新当月月报，列出 context 候选，暂不修改 context |
| 部分采纳 | `确认 2026-09-22-C01、C03，写入 context，其余先保留。` | 仅应用该日期下获准条目，记录确认范围与结果 |
| 直接记录 | `把“以独立供者为推断单位”这个决定记入 context。` | 在明确授权范围内直接写入，不重复询问同一许可 |
| 精简 | `context 太长了，请提出精简方案，保留有效约束和历史依据。` | 展示新增、替换与迁出的具体变化及历史去向，供确认 |
| 主题拆分 | `队列设计和通路分析都要长期维护，请提出 context 拆分方案，先供我审阅。` | 展示各文件职责、转移内容及新总入口；确认后再建立主题文件和路由 |

想先看内容而不保存文件，可以说：`总结当前阶段，只在聊天中预览，暂不落盘。`

## 后续维护 AGENTS.md

`research-context` 负责初始生成和项目上下文约定。**只有你明确要求审查、精简或迭代 AGENTS.md 时**，才使用 [agents-md-maintainer](../agents-md-maintainer/SKILL.md)。模板保留这条按需维护入口；日常任务、生成指令、恢复项目、维护 context 或模型升级本身，都不会附带启动这项维护流程。

后续可以这样调用：

```text
$agents-md-maintainer
审查当前项目的 AGENTS.md，先给维护建议和最小 diff，不修改文件。
```

你明确要求结合模型升级审查时，补充实际的旧模型与目标模型标识，由维护 Skill 将适用的 OpenAI 官方指南与项目证据对应到具体规则；模型能力提高本身不代表已有规则可以删除。审阅后可说：`应用本次报告的 R01、R03，保留其他候选。`

已批准的项目维护结果会保留，后续使用 research-context 不会用初始模板将其覆盖。若希望改进也用于未来新项目，可再要求：`将本次已批准且适合通用化的改进同步到 research-context 的生成规则和 AGENTS.md 模板，保留项目特例。` 这样，项目维护与生成能力迭代分别在明确范围内进行。

两个 Skill 分别使用；这项接口不自动安装维护 Skill。若当前会话未发现它，可以提供其 `SKILL.md` 的实际路径供 Agent 读取。

## 月报怎样记录

“总结今天”或“总结当前阶段”会立即更新所属月份的文件，无须等到月底。每个月一份，内部按工作日期和时间升序排列；同日只补充新增进展，补记放回对应日期，并保留实际整理时间。

每次回顾包含四项：

1. **做了什么：** 已完成、进行中、阻塞及对应产物，区分计划、执行与核验。
2. **拒绝或暂缓了什么：** 决定者、理由、适用范围及重启条件；区分用户拒绝、待回复建议、暂缓和技术失败。
3. **生信分析做了什么：** 输入与样本版本、方法、结果、核验范围和推断限制，包括不显著或相反结果。
4. **哪些值得放入 context：** 列出新增、替换、迁出候选，以及依据和必要恢复线索。

记录区分工作日期、整理时间和确认时间，带明时区；沿用用户或项目设置，默认 `Asia/Shanghai`。同时说明本次覆盖的对话、记录及产物，不把无法看到的任务写成“没有做过”。

候选用“日期＋条目编号”定位，例如 `2026-09-22-C01`。总结请求本身不代表同意更新 context；部分确认只应用指定内容。**确认存档不等于科学结论成立**，暂定解释、待核验事项和不确定性仍保留原有性质。

## 分析进展索引与渐进式披露

主 `context.md` 靠前放一张简短的分析进展表，让人直接看到“做到了哪一步、各步得到了什么、详情在哪里”。步骤沿用项目实际生信分析流程；多队列或分支进度不同时标明对象，不强行归成同一个完成状态。

下面仅为格式示意，不代表项目已有这些结果或文件。实际索引使用已核对的内容，并将位置写成可点击的文档或章节链接：

| 分析步骤 | 当前进展 | 主要结果 | 详细记录位置 |
| --- | --- | --- | --- |
| 数据收集与整理 | 已完成 | 已确定纳入的数据集和样本分组 | 现有分析记录的“数据整理”章节 |
| 质量控制 | 进行中 | 有异常样本待复核，尚未决定排除 | 现有分析记录的“质量控制”章节 |
| 差异表达分析 | 等待样本与设计方案确定 | 尚无结果 | 本 context 的“差异表达分析”章节 |

每行只保留简短进展、关键结果和影响当前判断的限制；方法、参数、完整统计及详细解释留在原有记录中。没有详细记录就如实说明，不为补全表格新建文件。索引可以直接指向同一 context 的章节，也可以指向已有分析文档或主题文件，无须先拆分 context。

Agent 先读短总入口中的索引、全局约束和当前焦点，再展开本次任务相关的步骤及必要上游记录；具体判断还缺证据时，才查看对应产物或历史片段。若只需了解整体进度，索引足够时就停止。长记录按标题或关键词定位，不因链接存在就读取全文、全部步骤或整月月报。

索引是详细记录的摘要，不是第二份独立维护的状态。获准更新时，同步相关正文与索引行，用新进展替换旧进展；保留待核验、无显著结果和相反证据的性质，不能把“已经运行”写成“已经验证”。索引也计入总入口的长度预算。

已有进展表和主题路由优先复用，获准整理时合并成适合当前项目的一份索引；普通恢复仍可读取旧格式，不自动转换，不并排增加第二套目录。详细规则见 [分析进展索引与渐进式披露](references/context.md#分析进展索引与渐进式披露)。

## context 怎样保持简短

总入口以 **4,000 个 Unicode 字符为软目标**，写入前检查预计长度。该数字不是模型 token 上限，也不是可以截断内容的硬限制；主题文件也保持紧凑，控制的是本次任务的累计读取量。

维护时采用替换式更新：

- 保留当前目标、有效约束、必要证据与输入版本、关键限制、阻塞和下一步。
- 用新状态替换旧进度，避免逐轮追加流水。
- 将已完成过程、过期状态和详细结果保存到月报，或引用已有产物；先核对历史去向，再应用获准迁出。
- 为暂停问题留下名称、恢复位置及重启条件；仍影响当前判断的拒绝理由和负面证据继续保留。

如果必要信息仍超出软目标，会完整保留并说明原因，提出缩小当前工作范围的具体方案；若主要由多个独立问题的有效状态造成，也可建议主题拆分。全局约束本身过长时，不能把它藏入主题来达标。

读取顺序、工具输出和恢复核对见下节；超长记录的完整扫描只用于明确请求的全面整理或核验。

## 怎样控制读取并恢复状态

新会话或会话压缩后，先核对短总入口、当前主题及必要依赖中的有效决定、输入版本、执行状态、未完成请求和下一步条件。摘要提供线索，关键状态须能回到持久化记录或实际产物；有冲突时说明缺口。已经核对且仍适用的信息可复用，不要求每轮重读。

大型表格先筛选对象和必要列，日志先定位相关任务或事件，搜索先返回路径与短摘要，再读取必要片段。完整内容留在原产物，控制每次工具返回量和本轮累计读取量。预览只用于认识结构，不能用前几行或被截断的结果证明没有反例；相关证据未核清时继续定向读取。已有材料足够时不加载月报或无关主题。

恢复时区分“已完成且核验”“已启动但待核验”和“尚未完成的请求”。例如旧摘要说分析已完成，但实际只留下启动日志，就先核对任务状态和结果，不能直接宣称完成或重复启动。恢复本身不授权修改 context；发现需持久化的变化仍沿用人工确认规则。

这些规则由 Agent 执行；随附脚本提供只读分页和来源变化校验，不自动监控会话预算、归档或开启 API 压缩。无需新增管理文件。详细规则见 [上下文恢复与更新](references/context.md)。

## 何时拆分主题 context

当多个研究问题各自仍有较多有效状态，并且不同任务只需要其中一部分时，可以经确认拆分。例如：

```text
docs/
├── context.md                   # 唯一总入口：全局约束、当前焦点、分析进展索引
├── context/                     # 确需拆分且获准时才创建
│   ├── cohort-design.md         # 队列设计的当前状态
│   └── pathway-analysis.md      # 通路分析的当前状态
└── monthly/
    └── 2026-09.md               # 工作过程和审核记录
```

拆分后，在同一张四列分析进展索引中更新相应步骤的“详细记录位置”，指向主题的必要章节。例如数据整理相关步骤可指向队列设计记录，通路分析步骤可指向通路分析记录，不再追加另一张主题路由表。旧“研究问题 / 何时读取 / 路径”格式继续可读，已明确批准的布局不会在恢复或拆分时被擅自转换。

`AGENTS.md` 仍只指向总入口，说明如何按需读取，具体主题路径在总入口维护。Agent 先读全局约束，再读当前问题及必要依赖；例如解释通路结果时，需要核对其依赖的队列决定，但不因此加载全部主题或月报。

每项详细状态只在一个位置权威维护：共有约束留在总入口，问题特有的输入版本、有效决定、限制、负面证据及下一步放在主题中；索引从中提取简短进展和结果。上游决定改变时，标出受影响主题的待重核状态，并将相关索引行的调整一同交由确认。主题内仍替换旧进度，历史继续归月报；暂停问题保留恢复位置和重启条件。

拆分前展示文件职责、转移内容和新总入口，按批准范围应用；明确授权的无损拆分可以直接执行。部分确认不扩大为全部拆分，目标内容核对保存后才切换路由。不会预建空文件、按日期轮换 context、机械切成 `context1/context2` 或不断增加索引层级。

## 文件与使用边界

日常仍只有上述三类管理文档；可选主题文件属于 context 这一类。默认单个 context，不额外创建独立索引文件、交接或审批文件。分析数据、脚本和结果仍是项目本身的产物，context 通过引用连接它们。

旧日报、主题记录和自定义入口继续可读，不自动迁移或删除。明确整理超长旧记录时，确需的来源快照和迁移进度集中放在 `temp/research-context-migration/` 下，核验完成后按授权清理；不会因精简上下文删除原始证据。

普通分析、切换任务或会话自动压缩不自动写月报和 context。重要阶段可以主动请求总结；已经丢失且未保存的信息无法保证事后找回。生效状态、待审阅建议和实际证据需要分别核对，不能把记录存在视为分析已验证。
