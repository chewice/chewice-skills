# 科研上下文

以研究问题组织当前状态、依据和下一步，用分析步骤串联进展、主要结果和详细记录位置，使人和新会话都能快速了解项目并按需展开。面向人的说明使用中文，专业术语、代码、路径及机器可读值保持英文。

## 共同原则

- 遵循第一性原理与 Occam's razor：明确研究问题、数据生成过程、比较对象和推断单位，选择足以改变判断的最小充分工作。在保障输入来源、样本与特征身份、统计推断、关键质量控制和必要可复现性的前提下减少重复计算、无用途产物与冗余管理，不以脚本数、行数或文件数衡量简洁。解释力相当时优先额外假设更少的解释；问题尚未确定时保留探索状态。
- 观察、解释与用户决定分别记录，事后发现不冒充事前设计。技术检查通过不代表假设成立；支持性、null、negative、contradictory 与 inconclusive evidence 同样保留。
- 日常管理只维护三类文档：`AGENTS.md` 保存稳定约定，context 保存获准的当前状态，月报保存过程与审核记录。context 默认只有一个短总入口；多个独立研究问题确需分别维护时，经批准增加少量主题 context，总入口仍唯一。详细证据引用已有分析产物；不靠反复总结旧摘要保存历史。确认存档不代表科学结论成立，也不代表永久留在启动入口。
- 读取与写入授权分开：可按任务需要恢复上下文；仅在用户请求总结或保存进展时生成待审阅记录，具体内容获准后才写入总入口或主题 context。明确“把这项记入 context”已是授权，无须再确认；日常分析、用户改变研究决定或会话自动压缩均不自动触发记录。
- 入口以 **4,000 个 Unicode 字符**为软目标，每次准备写入时检查预计长度；以替换旧状态、引用细节控制增长，不自动提高预算。字符预算不代表模型 token 上限，不能为达标删去有效约束。
- 总入口保留全局约束、当前焦点及“分析步骤 / 当前进展 / 主要结果 / 详细记录位置”索引；先读入口，再展开当前步骤的已有记录及必要依赖，最后按具体缺口核对产物。工具返回前筛选必要片段，控制单次与累计读取量；跨会话或压缩后核对恢复状态，不将摘要当作完成证明或新授权。索引只摘要详细记录，不另行维护一份完整状态。
- 沿用项目布局，不预建主题目录或文件，不另建独立索引、交接或审批文档。旧日报、主题记录和自定义入口继续可读，不自动迁移或删除；迁移辅助材料仅在明确整理任务中按需建立：必要恢复与追溯证据沿用可靠存档位置，仅可重建且无唯一证据的工作副本放临时目录。`records/` 等证据位置不另行维护 context 或月报的状态正文。
- Main Agent 统一维护入口和共享研究记录；Sub-agent 返回更新建议，或写入明确分配且不冲突的独立产物。

## 按需加载

- 用户要求生成项目 `AGENTS.md` 或合并已获准的上下文约定：按下节生成规则使用 [`assets/AGENTS.md.template`](assets/AGENTS.md.template)。
- 仅当用户明确要求审查、精简或迭代现有 `AGENTS.md` 时，使用 `agents-md-maintainer`，按下述后续维护接口处理。
- 恢复项目、维护分析进展索引、控制工具输出、核对来源或写入已获准内容：读取 [`references/context.md`](references/context.md)。
- 总结当日/阶段工作、保存进展、准备或确认上下文变更：读取 [`references/monthly-review.md`](references/monthly-review.md)；实际写入时再按 `references/context.md` 核对入口。
- 记录过长、需要评估主题拆分，或用户明确要求整理迁移：再读取 [`references/long-projects.md`](references/long-projects.md)，普通恢复不启动完整扫描或改写。
- 委派、交接或核验：读取 [`references/delegation.md`](references/delegation.md)。

## 生成项目指令

- 模板是生成起点，只提取稳定的 Agent 行为要求、授权边界和必要文档入口；不把项目材料概括成一份项目管理说明。沿用指定的指令位置，否则使用项目根 `AGENTS.md`；已有文件只合并授权内容，保留有效项目规则与例外，不整份覆盖。
- 逐条判断内容是在约束 Agent 如何工作，还是在描述项目做什么、如何运行、目前做到哪里。项目简介、目录清单、脚本顺序、数据路径、环境版本、运行命令、具体科学定义与阈值不写入生成文件；沿用已有项目说明、方法文档或代码，确有需要时只保留带读取时机的可靠入口。当前进展、阻塞和下一步属于 context；“本次初始化不创建”等单次操作说明只在本轮回复中交代。缺少承接文档不授权顺带创建、迁移或改写它。
- 默认不生成“项目定位”“目录与运行约定”“执行与核验”“数据保护”等独立章节。必要的执行授权、破坏性操作边界和如实报告要求简短并入工作方式；不擅自增加“任何测试都需另行确认”或“任何项目外读取都需确认”等权限限制，也不放宽用户已有的明确限制。用户明确要求保留的项目特例优先，不能以精简为由删除。
- 将模板中的 README 管理约定带入项目指令：项目自行维护的 README 只设根目录一份，沿用已有大小写命名；未经明确要求，不在子目录创建 README 或因脚本运行、结果生成而自动增加说明文件。保留来源材料与第三方工具自带的 README，不自动清理已有子目录 README。生成指令本身不授权创建或改写根 README；用户明确要求的例外按其范围执行。
- 将模板中的正式代码与结果可追溯、证据与临时内容分开、日志按用途保存和 Git 忽略保护带入工作方式。这些是稳定行为约束，不是项目目录清单；具体保存语法、修补纳入正式流程和迁移核验由 `scripting-style` 提供，不在本 Skill 复制实现细节。
- 将编号阶段输出约定带入生成的工作方式：编号分析流程沿用脚本对应的编号输出目录；每阶段可保存多个产物，所需覆盖与例外表也归本阶段，下游显式读取上游目录。未经用户明确指定，不将多个阶段混放到新共享目录或输出根目录。这是稳定职责约束，不复制具体脚本清单；非编号的独立分析沿用清楚的既有布局。仅生成指令不授权迁移已有文件。
- 生成前核对已有目录职责与用户约定，替换模板中对应的目录名及 Git 忽略条款，不把默认路径强加给已有项目。无既定布局时采用 `scripts/`、`output/`、`records/`、`tmp/`、`output/run_logs/` 作为按需使用的约定；默认输出和临时内容不纳入 Git，必要的小型代码与记录可版本管理，大型证据按项目策略处理。初始化 AGENTS/context 本身不授权预建这些目录、迁移文件或修改 `.gitignore`。代码与结果对应指可追溯，不限制文件数量，也不把第三方来源包中的脚本视为需要迁走的辅助代码。
- 定向核对用户指定或项目既定的唯一上下文入口。把模板中的 `{{CONTEXT_ENTRY_RULE}}` 替换为包含实际项目相对路径的入口规则；路径以生成的 `AGENTS.md` 所在目录为基准，不迁移或重命名既有入口。
- 只有请求包含建立上下文时才创建缺失的 `context.md`，位置与最小内容见 [`references/context.md`](references/context.md)。若仅生成指令且尚无入口，使用条件规则“恢复时使用用户指定或项目已确定的唯一上下文入口；入口缺失时继续有依据的工作，仅在用户要求建立后创建”，不把“当前尚未建立”写成长期状态，不声称默认路径已经存在，不留下占位符。
- 上下文部分只保留入口、按需读取、证据适用性和写入授权。字符预算、分页指纹、主题拆分、迁出流程及共享记录维护细节由 `research-context` 按需提供，不复制到生成文件。动态主题路径与读取路由放在总入口；月报路径、正文及读取清单也不写入 AGENTS.md。一次拒绝或失败不自动升级为永久规则。缺少资料时不虚构分析方案或已批准决定。
- 生成后核对：每条都提供行为约束或必要入口，没有夹带项目事实与临时状态；引用可达且注明何时读取；已有授权与保护义务保持。日常恢复或单独维护上下文不重建 `AGENTS.md`；不把本次模板审查变成每次生成的必经流程，也不自动安装模板引用的 Skill。

## 后续维护接口

- 生成的 `AGENTS.md` 保留一句仅由用户明确请求触发的 `agents-md-maintainer` 维护入口，不复制审计流程或固定模型版本。日常任务、生成指令、恢复项目、维护 context 或模型升级本身均不自动启动该维护流程。用户请求审查后，沿用该 Skill 的先给建议、获准后应用约定；明确要求结合模型升级审查时，再使用指定目标模型、适用的 OpenAI 官方指南与项目证据判断。
- 模板是初始生成依据，不覆盖后续已批准的项目维护结果。项目中的改动不自动回写本 Skill；用户要求将已审阅的通用改进用于今后生成时，再同步生成规则与模板，项目特例仍留在项目。调用示例见 [README](README.md#后续维护-agentsmd)。
