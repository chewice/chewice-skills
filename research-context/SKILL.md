# 科研上下文

以研究问题组织当前状态、依据和下一步，使新会话可以从项目文件恢复工作。面向人的说明使用中文，专业术语、代码、路径及机器可读值保持英文。

## 共同原则

- 遵循第一性原理与 Occam's razor：明确研究问题、数据生成过程、比较对象和推断单位，选择足以改变判断的最小工作。解释力相当时优先额外假设更少的解释；问题尚未确定时保留探索状态。
- 观察、解释与用户决定分别记录，事后发现不冒充事前设计。技术检查通过不代表假设成立；支持性、null、negative、contradictory 与 inconclusive evidence 同样保留。
- 日常管理只维护三类文档：`AGENTS.md` 保存稳定约定，context 保存获准的当前状态，月报保存过程与审核记录。context 默认只有一个短总入口；多个独立研究问题确需分别维护时，经批准增加少量主题 context，总入口仍唯一。详细证据引用已有分析产物；不靠反复总结旧摘要保存历史。确认存档不代表科学结论成立，也不代表永久留在启动入口。
- 读取与写入授权分开：可按任务需要恢复上下文；仅在用户请求总结或保存进展时生成待审阅记录，具体内容获准后才写入总入口或主题 context。明确“把这项记入 context”已是授权，无须再确认；日常分析、用户改变研究决定或会话自动压缩均不自动触发记录。
- 入口以 **4,000 个 Unicode 字符**为软目标，每次准备写入时检查预计长度；以替换旧状态、引用细节控制增长，不自动提高预算。字符预算不代表模型 token 上限，不能为达标删去有效约束。
- 总入口保留全局约束、当前焦点及必要主题路由；先读入口，再读当前问题及必要依赖，不递归加载所有链接。每项状态只在一处权威维护，历史不靠不断新建 context 保存。
- 沿用项目布局，不预建主题目录或文件，不另建专题索引、独立交接或审批文档。旧日报、主题记录和自定义入口继续可读，不自动迁移或删除；迁移临时文件仅在明确整理任务中按需建立。
- Main Agent 统一维护入口和共享研究记录；Sub-agent 返回更新建议，或写入明确分配且不冲突的独立产物。

## 按需加载

- 用户要求生成项目 `AGENTS.md` 或合并已获准的上下文约定：按下节生成规则使用 [`assets/AGENTS.md.template`](assets/AGENTS.md.template)。
- 仅当用户明确要求审查、精简或迭代现有 `AGENTS.md` 时，使用 `agents-md-maintainer`，按下述后续维护接口处理。
- 恢复项目、核对来源或写入已获准内容：读取 [`references/context.md`](references/context.md)。
- 总结当日/阶段工作、保存进展、准备或确认上下文变更：读取 [`references/monthly-review.md`](references/monthly-review.md)；实际写入时再按 `references/context.md` 核对入口。
- 记录过长、需要评估主题拆分，或用户明确要求整理迁移：再读取 [`references/long-projects.md`](references/long-projects.md)，普通恢复不启动完整扫描或改写。
- 委派、交接或核验：读取 [`references/delegation.md`](references/delegation.md)。

## 生成项目指令

- 模板是生成起点，按用户约定和项目事实调整。沿用指定的指令位置，否则使用项目根 `AGENTS.md`；已有文件只合并授权内容，保留有效项目规则与例外，不整份覆盖。
- 定向核对用户指定或项目既定的唯一上下文入口。把模板中的 `{{CONTEXT_ENTRY_RULE}}` 替换为包含实际项目相对路径的入口规则；路径以生成的 `AGENTS.md` 所在目录为基准，不迁移或重命名既有入口。
- 只有请求包含建立上下文时才创建缺失的 `context.md`，位置与最小内容见 [`references/context.md`](references/context.md)。若仅生成指令且尚无入口，替换为“当前尚未建立上下文入口；继续有依据的工作，仅在用户要求建立上下文后创建”，不声称默认路径已经存在，不留下占位符。
- `AGENTS.md` 只保留稳定协作约定、唯一总入口、按需加载规则和审核边界；动态主题路径及读取条件放在总入口，不写入 AGENTS.md。月报路径、正文、读取清单或维护流程也不写入；详细流程由 Skill 按需加载。一次拒绝或失败不自动升级为永久规则。缺少资料时不虚构数据路径、分析方案或已批准决定。
- 生成后检查入口和约束与项目一致。日常恢复或单独维护上下文不重建 `AGENTS.md`；不把本次模板审查变成每次生成的必经流程，也不自动安装模板引用的 Skill。

## 后续维护接口

- 生成的 `AGENTS.md` 保留一句仅由用户明确请求触发的 `agents-md-maintainer` 维护入口，不复制审计流程或固定模型版本。日常任务、生成指令、恢复项目、维护 context 或模型升级本身均不自动启动该维护流程。用户请求审查后，沿用该 Skill 的先给建议、获准后应用约定；明确要求结合模型升级审查时，再使用指定目标模型、适用的 OpenAI 官方指南与项目证据判断。
- 模板是初始生成依据，不覆盖后续已批准的项目维护结果。项目中的改动不自动回写本 Skill；用户要求将已审阅的通用改进用于今后生成时，再同步生成规则与模板，项目特例仍留在项目。调用示例见 [README](README.md#后续维护-agentsmd)。
