# EndNote → Zotero 动态引用迁移

在 SKILL.md 判定当前请求是轨道 B 之后阅读本文件。本文件把「文献身份—正文引用—文献表」从 EndNote 动态字段迁到 Zotero 动态字段；不授权覆盖原稿，也不授权在未批准映射表之前写字段。

## 何时读

- 源 DOCX 含 EndNote 引用或文献表字段；
- 用户要把后续增删、重编号交给 Zotero；
- 需要可交付给他人复核的审计包，而不是一份「看起来正常」的 DOCX。

不适用于已「转换为纯文本」或已移除字段代码的文档。

## 建议准备的输入

- 含 EndNote 动态字段的原始 DOCX（只读）；
- 原 EndNote 文献库及其配套数据目录（只读，用于回滚和补充核对）；
- 从 EndNote 导出的结构化 XML 元数据；
- 原 EndNote 输出样式文件（可选，只比较格式，不定身份）；
- 不与日常 Zotero 主库混用的隔离 profile 和独立数据目录，见 `references/zotero-profiles.md`；
- 独立工作目录，存放候选稿、映射表和审计报告。

EndNote 导出界面的 Output Style 主要控制格式化输出。用于身份匹配的结构化 XML，关键是元数据字段本身；不必为了让样式选择框为空而中断流程。

## 阶段 1：建立只读基线

解析原稿中的：

- EndNote 正文引用字段及其出现次数；
- 唯一文献身份；
- EndNote 文献表字段；
- 现有修订、批注、表格、图形和分页；
- 正文可见文本与引用显示文本。

基线的作用是回答「迁移后究竟有没有改变正文或版式」，而不仅是记录文件能够打开。保留源文件大小和 SHA-256。

## 阶段 2：提取稿件实际引用的文献子集

EndNote 的 All References 通常是整个文献库，数量可能远大于稿件实际引用数。不要把全库直接导入隔离 Zotero 环境。

正确做法：

1. 保留完整 XML 作为来源；
2. 根据 DOCX 中的引用身份提取 cited-only 子集；
3. 检查子集是否覆盖每一篇唯一引用文献；
4. 只把该子集导入隔离 Zotero profile。

## 阶段 3：在隔离 Zotero 环境中建立快照

隔离 profile 应满足：

- 使用独立数据目录；
- 不自动同步日常主库；
- 只含当前稿件的候选文献；
- 能通过条目总数和若干已知题名确认库身份。

导入后，从 Zotero 获取只读条目快照。快照用于稳定匹配，不应在匹配过程中边改库边生成字段。创建与切换步骤见 `references/zotero-profiles.md`。

## 阶段 4：逐项身份匹配

推荐优先级：

1. DOI 精确匹配；
2. PMID 精确匹配；
3. ISBN 精确匹配；
4. 规范化题名加年份；
5. 作者、卷期页码等辅助核对。

匹配结果至少分为：精确、候选、缺失、重复、歧义。不要用相似度最高自动替代人工判断，也不要因为显示编号相同就认为文献身份相同。

## 阶段 5：人工批准门

在生成迁移 DOCX 之前，由人工逐项确认映射表。最低批准条件：

- 每篇源文献对应且仅对应一个 Zotero 条目；
- 没有缺失、重复或未解释的歧义；
- DOI 等稳定标识符一致；
- 无标识符条目已核对题名、年份和作者；
- 人工明确批准继续，并确认不覆盖原稿。

没有 100% 人工批准，不进入字段迁移阶段。自动匹配分数只能帮助排序，不能代替批准。

## 阶段 6：按完整字段块迁移正文引用

Word 引用不是普通文本。应以完整字段结构为单位，将 EndNote 引用替换为含稳定 Zotero URI 的 `ZOTERO_ITEM` 字段，同时保持：

- 原引用位置；
- 多文献组合关系；
- 前后标点和空格；
- 正文可见文本；
- 表格、脚注或其他容器中的字段边界。

禁止只改上标数字、直接搜索替换引文显示文本，或在字段起止标记之间做普通文字编辑。源文件仍不可变；只写 candidate。

若还没有通用脚本完成这一步，停在「已批准映射 + 未写字段的 candidate 计划」，列出还缺的实现，不要用临时搜索替换凑一篇「看起来像 Zotero」的文档。

## 阶段 7：由 Word 与 Zotero 完成本地刷新

仅在用户明确授权 live 集成后执行。先读 `references/live-refresh-protocol.md`。

1. 保持目标 Zotero profile 单独运行；
2. 打开迁移候选稿，而不是原稿；
3. 关闭 Word 修订功能；
4. 在 Zotero 选项卡中设置目标 CSL 样式；
5. 执行 Refresh，确认正文引用没有报错；
6. 删除旧 EndNote 文献表字段；
7. 使用 Add/Edit Bibliography 建立 Zotero 文献表；
8. 再次 Refresh，另存为新的最终候选稿。

Refresh 属于字段重建操作，不应在开启修订时执行。正文内容修改需要修订痕迹时，应与引用刷新分开进行。

## 人工与自动化的职责边界

| 决策点 | 自动化负责 | 人工负责 |
|---|---|---|
| 范围确定 | 统计字段与唯一文献 | 确认操作对象和不可覆盖的原稿 |
| 文献匹配 | 按标识符生成候选和证据 | 批准每一项身份映射 |
| 样式选择 | 比较显示差异 | 决定采用标准 CSL 还是复刻旧样式 |
| 插件刷新 | 准备合法字段结构 | 在 Word/Zotero 原生界面执行并观察报错 |
| 最终验收 | 字段审计、文本比较和渲染 | 确认视觉效果与交付标准 |

## 常见失败模式与处理

### 1. EndNote 全库远大于稿件引用量

原因：导出的是整个库，而不是稿件 cited-only 集合。

处理：保留完整导出作为来源，从 DOCX 引用身份中提取子集后再导入 Zotero。

### 2. Zotero Refresh 正常，但 Add/Edit Bibliography 没有生成内容

先检查：

- 光标是否位于正文末尾的普通空段落；
- 文档是否已经存在旧文献表字段；
- 正文是否确实包含可解析的 Zotero 引用字段；
- 当前运行的 Zotero 是否为正确 profile；
- Word 是否有隐藏对话框或修订状态干扰。

如果仍无报错且文献表为空，可以在预定位置建立一个标准 `ZOTERO_BIBL` 字段，再由 Zotero Refresh 填充。自动化只建立字段容器，不应自行拼接最终文献表文本。

### 3. 迁移后样式与 EndNote 不完全相同

先区分两类问题：

- **身份或编号错误**：必须修复；
- **标点、作者缩写或 DOI 呈现差异**：属于 CSL 样式选择。

只有在交付方明确要求旧格式逐项一致时，才编写自定义 CSL。否则优先采用已确认的标准 Zotero 样式。

### 4. 引用刷新后出现大量修订痕迹

原因：执行 Zotero Refresh 时开启了 Word 修订。

处理：恢复候选稿副本，关闭修订后重新刷新；不要试图逐项接受海量字段内部修订。

### 5. Word 连接到错误的 Zotero 库

原因：同时运行多个 profile 或实例，且 Word for Windows 不能在同一系统用户下指定其中某一个实例。

处理：关闭 Word 和所有 Zotero 实例，只启动目标 profile，确认库身份后再打开 Word。见 `references/zotero-profiles.md`。

## 验收标准

### 结构一致性

- 目标 Zotero 引用字段数＝源 EndNote 引用出现次数；
- 唯一 Zotero 条目数＝人工批准映射数；
- Zotero 文献表字段恰好为 1；
- EndNote 正文引用和文献表字段均为 0；
- 所有字段起止标记平衡，没有嵌套破损。

### 内容一致性

- 文献表前的正文可见文本与迁移基线一致；
- 每个引用位置的文献集合一致；
- 编号型样式下，正文编号与文献表编号均完整连续；
- 新增或删除引用后，编号由 Zotero Refresh 自动重算，而非人工修改。

### 视觉一致性

- 使用 Word 原生渲染全部页面；
- 逐页检查裁切、重叠、缺字、表格越界、异常空白页和参考文献跨页；
- 对比迁移前后的正文分页；
- 核对最后一条文献完整收尾。

### 可回滚性

- 原稿和原文献库未被覆盖；
- 映射表、批准记录、候选稿、最终稿和审计报告相互可追踪；
- 发生问题时可以退回「已批准映射＋未刷新候选稿」重新执行，而不必从头处理原稿。

## 后续编辑的维护规则

- 修改普通正文时避开字段内部；
- 新增引用使用 Zotero Add/Edit Citation；
- 删除引用通过 Zotero 引用编辑器完成，不只删除屏幕上的编号；
- 调整字体和段落时，分别检查正文样式、引用字符样式与 Bibliography 段落样式；
- 每次批量内容修改后执行 Refresh、结构审计和局部渲染；
- 最终交付前再次执行完整逐页检查。

## 适合交付的成果包

- 未修改的原始 DOCX；
- 稿件实际引用的 cited-only 元数据；
- 自动匹配候选表与人工批准表；
- Zotero 字段迁移候选稿；
- 经 Word/Zotero 刷新的最终稿；
- 字段结构、正文一致性和视觉 QA 报告；
- 简短操作说明，注明使用的 Zotero profile、CSL 样式和刷新时间，但不暴露个人路径或账号信息。

交付目录本身仍只放完成版 DOCX 和原稿副本；上列其余文件留在 run root，除非用户明确要求一并交付。
