# 生物医学输入说明

在首次检查数据、决定分组比较或改变输入对象时读取。说明写在现有 BRIEF/RESULT 的输入位置，或引用项目已有数据说明；不预建注册系统，不要求另存一份重复样本表。只记录当前分析需要且已经核实的内容，未知项写明待核实。

## 样本关系

先回答：矩阵的一行/列是什么？实验处理或暴露发生在哪一层？哪些观测来自同一个独立生物学单位？

按实际数据引用 `donor → sample → library → cell` 等关系；动物、类器官、切片、空间 spot、重复随访等采用实际单位，不强套 donor 层级。区分 biological replicate 与 technical replicate，记录分组、配对、时间和批次中会影响本次比较的字段。

已有样本表直接引用路径、版本与相关列名。确实缺少时才在现有数据目录按需建立一张表，列名跟随项目惯例，例如：

| donor_id | sample_id | library_id | group | time | batch |
|---|---|---|---|---|---|
| D01 | S01 | L01 | treated | baseline | B1 |
| D01 | S02 | L02 | treated | followup | B2 |

上例中的两个 sample 来自同一 donor；不能只凭两个 library 就声称有两个独立生物学重复。cell/spot 到 sample 的映射可以保留在对象 metadata 中，无需复制所有细胞到样本表。

首次 join、分组或模型拟合前，直接检查所用 ID 的唯一性/覆盖、映射基数、缺失分组及各组独立单位数量。按实际设计查看配对关系与 group/batch 分布；不要让 merge 静默增加行数或丢失样本。无法确认独立单位时可继续描述数据，但不能据此宣称组间推断已可靠。

## 输入数值的含义

按当前 assay 选择适用信息，不把下表变成每个项目必填的检查表。

| 输入 | 需要说清楚的含义 |
|---|---|
| 表达矩阵 | 物种、行列含义、gene ID 体系及版本、参考基因组/注释版本（若已知），counts/normalized/log-transformed 等数值状态 |
| Seurat / AnnData | 文件来源与版本、实际使用的 assay/layer/slot 或矩阵、关键过滤/归一化/整合步骤、sample 映射所在列 |
| peaks / intervals | 参考基因组、染色体命名、坐标起点及区间约定、数值是计数还是归一化信号 |
| 临床/表型表 | 个体与访视标识、单位、取值编码、时间定义、缺失值约定、分组/结局定义 |

这些信息应来自数据说明、生成代码或对象检查，不能从文件名猜出 genome build 或从矩阵非整数值断定某一种变换。原始输入说明放 BRIEF 或已有数据说明；本次实际选择的 layer、处理状态和偏离放 RESULT，重复输入只引用。

例如：`cohort.h5ad；sample metadata 见 samples.tsv；obs.sample_id 映射 sample；layers["counts"] 来自生成脚本记录的原始计数；基因 ID 为 Ensembl；参考注释版本待核实。` 不确定信息影响某一步判断时，先核实，再做依赖它的分析。

本说明帮助研究者作科学判断；结构 Validator 不读取大型矩阵、不自动选择推断单位，也不证明样本独立性或数据适用于某统计模型。
