# 输出约定

## 输出角色

按用途选择一种或多种产物，不要求每个脚本同时生成全部类型：

- **对象**：昂贵计算或下游继续分析所需的完整状态。
- **表格**：可检查、比较、汇总或进入其他工具的结果。
- **图形**：QC、方法诊断、生物学解释和最终展示。
- **日志摘要**：运行阶段、关键数量和已生成文件。

若结果需要人工复查、下游复用或重新绘图，再分别保存对应表格、对象或摘要；没有这些
需求时，不为凑齐类型制造冗余文件。

## 路径与命名

- 在写入前显式定义输出目录，并按当前项目约定创建。
- 输出目录默认使用相对于 repository / runner 既定 working directory 的路径；同一脚本与
  输入共用一个明确锚点。
- 不把输出写死到用户目录、机器安装目录、绝对盘符或 `~`；迁移项目后应保持输入—输出
  关系不变。
- 文件名表达阶段、分析对象、比较或 lineage、产物类型。
- 同一主干的图、表和对象使用可关联的 stem。
- 不覆盖输入文件；是否允许覆盖由当前项目和用户要求决定。
- 不复制范例中的绝对路径，也不新建机器特定绝对输出路径。

示例结构仅表达命名关系：

```text
<stage>-<analysis>-<comparison>.csv
<stage>-<analysis>-<comparison>.png
<stage>-<analysis>-object.qs
```

不要把尖括号占位符原样留在真实文件名。

## 保存时机

- 关键转换完成并检查后保存昂贵中间对象。
- 结果整理完成后立即保存表格。
- 图形生成后立即保存，并显式给出适合任务的尺寸和分辨率。
- 在脚本结束打印简短摘要：关键数量、输出目录和主要文件。

## 完整性检查

- 输出目录是否存在？
- 输出路径是否相对于已说明锚点，且能随项目目录整体迁移？
- 表格是否包含稳定标识符和必要列？
- 图形分组、颜色、标签和比较方向是否清楚？
- 对象是否能被明确的下游步骤读取？
- 输出名能否区分不同参数、stage 或 lineage？
- 是否产生了没有下游用途的临时文件？

交互式 `View()` 可以用于探索，但不能是唯一检查或唯一输出。
